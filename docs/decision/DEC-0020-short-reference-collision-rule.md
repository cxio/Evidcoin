# DEC-0020: 短引用歧义的协议级处理

## Status（状态）

Accepted

## Context（背景）

`conception/附.交易.md` 允许非首领输入使用 ≥16 字节的短引用以节省空间，并指出当出现潜在塑造攻击时可由被引用方自行延长输入引用以规避歧义。该规避机制要求节点对"歧义短引用"采取一致的拒绝行为，否则不同实现可能对同一笔交易做出不同的解释，导致共识分裂或选择性执行漏洞。

## Decision（决策）

节点在交易验证阶段对短引用的处理遵循下列硬规则：

- 对每个非首领输入的短引用，在当前 UTXO/UTCO 缓存中按"年度分区 + 前缀匹配"查找。
- 若匹配到 **0 项**：交易非法，拒绝。
- 若匹配到 **1 项**：解析为该唯一项，继续后续验证。
- 若匹配到 **≥2 项**（短引用歧义）：交易非法，拒绝；不得依据任何"先到、最早、最大金额"等启发式选择其一。

补充约束：

- 拒绝行为发生在交易接收、内存池入池与区块验证三处，且行为一致。
- 节点不得在歧义命中时尝试自动延长引用代为修复，应由交易作者重新构造交易。
- 钱包实现负有协助义务：在构造输入时应主动检查目标 UTXO 缓存中前缀冲突，必要时延长引用直至无歧义；该义务为钱包工程实践，不属于共识规则。

## Rationale（理由）

- 统一的拒绝行为消除节点间对同一交易的解释差异，是变长短引用安全使用的协议前提。
- 启发式选择会引入二次塑造空间（攻击者可设计满足某种启发式的歧义集合），必须排除。
- 把修复责任交回交易作者，与 conception 中"被引用方延长引用即可化解"的设计一致。

## Consequences（影响）

- 实现层须保证 UTXO/UTCO 缓存的查找返回"匹配集合"而非"任一匹配项"，以便正确判定歧义。
- 测试向量应覆盖：唯一匹配、零匹配、二项歧义、跨年度同前缀、首领输入与短引用混合等场景。
- 钱包应在交易签名前完成歧义检查；未检查直接广播会导致交易被全网拒绝。

## Conception Relationship（与构想关系）

- 补充 `conception/附.交易.md` 中短引用机制的协议级拒绝行为。
- 不改变短引用最小长度 16 字节与变长策略，也不改变首领输入必须使用全长 48 字节的规定。
