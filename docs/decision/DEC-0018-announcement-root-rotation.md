# DEC-0018: 全网通告授权根的链上演化

## Status（状态）

Accepted

## Context（背景）

`DEC-0013` 把创世 `#0` 与 `#1` 区块的签名公钥定为全网通告授权根。该决策建立了客户端展示层的初始信任锚，但未给出根公钥本身的升级、轮换或撤销路径。若根公钥泄露、丢失、或长期不再具备社会认可，按 `DEC-0013` 现状无可恢复机制，会形成单点永久绑定。

## Decision（决策）

授权根支持通过链上多签 Proof 通告进行演化，形成可审计的信任链：

- 任意时刻存在一个**当前授权根集合** `R = { rootKey_i }`，初始为创世 `#0` 与 `#1` 区块的签名公钥（按 `DEC-0013`）。
- 根集合的演化通过特定标题的 Proof 通告完成：
  - 新增根：`Announcement:Root:Add:` —— 携带新增公钥及其简要说明。
  - 撤销根：`Announcement:Root:Revoke:` —— 携带被撤销公钥指纹。
  - 轮换根：`Announcement:Root:Rotate:` —— 等价于一次原子的"新增 + 撤销"。
- 演化通告必须由当前根集合中至少 `ceil(|R| / 2) + 1` 个不同根公钥的多签共同签发；当 `|R| = 1` 时退化为单签，但应在通告中同步追加至少一个新根，避免单点永存。
- 撤销通告生效后，被撤销公钥不再出现在 `R` 中；其历史签发的通告本身仍然有效（仅授权事实变更，不追溯历史）。
- 客户端按时间顺序回放所有 Root 演化通告以重建当前 `R`，并以此判定后续 `Announcement:<Level>:` 通告是否可被作为官方通告展示。
- 通告冲突仍按 `DEC-0013`：授权来源高度越低，权威性越高；当多签来源混合多个高度时，取签署者中最低的授权根高度。

## Rationale（理由）

- 多签门槛保证单一根公钥泄露不足以独立改写授权状态。
- 链上回放保留完整审计轨迹，与"展示层信任链"的定位一致。
- 不引入任何共识层强制规则，授权状态仍仅影响客户端展示，不影响区块或交易合法性。
- 退化为单签的过渡形态仅在创世初期或灾难恢复后短暂存在，并强制同步引入新根以避免再次单点。

## Consequences（影响）

- 客户端必须维护授权根集合的增量状态，而非仅记录初始两枚公钥。
- 授权根私钥应由项目方采用多人独立保管（推荐硬件密钥），并定期通过 `Rotate` 通告演练轮换流程。
- 演化通告本身需使用与普通 Proof 相同的链上发布机制；客户端在确认 29 块之前不应将其纳入授权状态。

## Conception Relationship（与构想关系）

- 补充 `conception/2.共识-端点约定.md` 中"全网通告"机制的授权生命周期，未改变其客户端展示层定位。
- 与 `DEC-0013` 共同构成授权根的完整生命周期描述：`DEC-0013` 定义初始锚点，`DEC-0018` 定义演化路径。
