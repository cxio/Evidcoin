# DEC-0016: 短引用歧义的协议级处理

## Status（状态）

Accepted

## Context（背景）

`conception/附.交易.md` 允许非首领输入使用至少 16 字节的短引用以节省空间，并指出当出现潜在塑造攻击时可由被引用方自行延长输入引用以降低歧义风险。最新构想层规则要求节点在短引用命中多个末端对象时采取确定性选择，而不是把交易判为无效。

## Decision（决策）

节点在交易验证阶段对短引用的处理遵循下列硬规则：

- 对每个非首领输入的短引用，必须基于被验证区块之前的规范 UTXO/UTCO 完整状态快照，按“年度分区 + 前缀匹配”查找。
- 若匹配到 0 项：交易非法，拒绝。
- 若匹配到 1 项：解析为该唯一项，继续后续验证。
- 若匹配到多个末端对象：在该规范匹配全集内按完整交易 ID 字节序升序排序，选择首个匹配项作为该短引用解析结果。

补充约束：

- 排序键使用完整交易 ID 原始字节，不使用短引用字节、不使用金额、高度、到达顺序或本地缓存顺序。
- 所有节点必须对同一匹配集合得到相同解析结果。
- 区块内交易不得引用未确认输出或同块新输出；短引用解析的状态边界与普通输入一致。
- 节点状态不完整时，不得使用本地部分缓存猜测解析结果；应补齐规范状态后再验证，无法补齐时不能接受该区块或交易为已验证。
- 钱包实现负有协助义务：在构造输入时应主动检查目标 UTXO/UTCO 缓存中的前缀冲突，必要时延长短引用以降低歧义风险；该义务为钱包工程实践，不属于共识规则。

## Rationale（理由）

- 完整交易 ID 字节序排序是可复现、与本地部分缓存无关的确定性规则。
- 在命中多个末端对象时仍可形成唯一解析结果，避免因短引用压缩导致可用交易被不必要地排除。
- 排除到达顺序、金额、高度等启发式字段，可减少实现差异和选择性执行空间。
- 钱包延长短引用仍是降低误引用风险的有效工程手段。

## Consequences（影响）

- 实现层须保证基于规范状态快照的 UTXO/UTCO 查找返回完整匹配集合，以便正确排序并选择首项。
- 测试向量应覆盖：唯一匹配、零匹配、多项命中、跨年度同前缀、首领输入与短引用混合等场景。
- 钱包应在交易签名前完成歧义检查；发现冲突时可延长短引用以表达更精确的目标。

## Conception Relationship（与构想关系）

- 补充 `conception/附.交易.md` 中短引用机制的协议级解析行为。
- 不改变短引用最小长度 16 字节与变长策略，也不改变首领输入必须使用全长 48 字节的规定。
