# DEC-0023: 脚本成本预算

## Status（状态）

Proposed

## Context（背景）

`conception/6.脚本系统.md` 已确定脚本执行成本预算属于协议层，并分为单个输入、单笔交易和单个区块三层。但具体数值和指令成本表尚未冻结，不能直接作为 Accepted 共识参数。

## Decision（决策）

本节为候选规则，状态转为 Accepted 前不得作为最终共识依据。

脚本成本预算框架固定为三层：

- `MaxInputScriptCost`：单个输入的最大脚本成本。
- `MaxTxScriptCost`：单笔交易的最大脚本总成本。
- `MaxBlockScriptCost`：单个区块的最大脚本总成本。

成本计算规则建议如下：

- 每条指令必须有确定性成本函数。
- 成本函数只能依赖指令码、附参、关联数据长度、实参类型和实参字节长度等共识可见数据。
- 成本函数不得依赖硬件性能、墙钟时间、节点本地负载、缓存命中率或实现语言。
- 签名验证、哈希计算、集合处理、脚本跳转和模块调用必须显式计费。
- 内存占用可作为独立维度或折算进统一成本，但折算公式必须确定。

成本检查位置：

- 执行单个输入的解锁脚本、锁定脚本和被引用脚本时累计输入成本，超过 `MaxInputScriptCost` 立即失败。
- 验证单笔交易时累计全部输入脚本成本，超过 `MaxTxScriptCost` 时交易非法。
- 构造或验证区块时累计区块内全部交易脚本成本，超过 `MaxBlockScriptCost` 时区块非法。

待冻结参数：

- `MaxInputScriptCost`。
- `MaxTxScriptCost`。
- `MaxBlockScriptCost`。
- 每个 opcode 的基础成本、动态成本因子和上限规则。
- 标准内置验证 `SYS_CHKPASS`、`FN_CHECKSIG`、`FN_MCHECKSIG` 的签名验证成本。

## Rationale（理由）

- 三层预算能同时限制单输入攻击、单交易聚合攻击和区块级资源耗尽。
- 确定性计费是公共验证一致性的必要条件。
- 先冻结框架可指导实现预留成本会计接口，具体数值可在基准测试后再接受。

## Consequences（影响）

- 当前实现不能宣称脚本成本共识参数最终冻结。
- VM 需要在执行路径上暴露成本累加与提前失败机制。
- 后续 Accepted 决策必须给出完整成本表和三层预算数值。

## Conception Relationship（与构想关系）

- 补充 `conception/6.脚本系统.md` 中三层脚本成本预算的实现框架。
- 不改变参数限定、脚本长度限制、跳转限制或执行成本属于协议层的构想层规则。
