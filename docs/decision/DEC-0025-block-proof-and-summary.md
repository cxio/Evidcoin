# DEC-0025: 区块证明包与概要短 TxID

## Status（状态）

Proposed

## Context（背景）

`conception/2.共识-端点约定.md` 允许区块在完整验证前通过适当的区块证明先行转播，`conception/附.组队校验.md` 也列出最少证明性数据。实现层需要固定区块证明包的最小字段，并明确概要短 TxID 仅用于网络同步优化时的碰撞处理。

## Decision（决策）

本节为候选规则，状态转为 Accepted 前不得作为最终共识依据。

区块证明包的最小字段建议为：

- 区块头。
- Coinbase 交易。
- Coinbase 到区块交易哈希树根的验证路径或必要关联哈希证明。
- 铸造者对 `CheckRoot` 的签名。
- 必要择优凭证，用于验证铸造者在对应择优池中的资格与铸凭哈希。

验证者在收到区块证明包后，只能据此执行快速转播判断；完整合法性仍需在获得完整交易 ID 序列、必要交易数据和状态证明后完成。

概要短 TxID 规则建议如下：

- 区块同步摘要可以使用 TxID 的前 16 字节作为短 TxID。
- 短 TxID 仅用于节点间识别本地已知交易、减少传输量，不进入区块头、TxID、CheckRoot 或任何共识哈希。
- 若同一区块摘要内或本地匹配集合中出现 16 字节前缀碰撞，接收方必须请求完整 TxID 或完整交易数据。
- 短 TxID 碰撞不得导致区块非法，也不得作为选择交易内容的共识依据。
- 完整验证阶段必须回到 48 字节完整 TxID。

待冻结参数：

- 区块证明包中择优凭证的精确字段和序列化顺序。
- Coinbase 验证路径对 UTXO/UTCO 指纹和 CheckRoot 的最小证明结构。
- 区块同步摘要消息的网络封装编码。

## Rationale（理由）

- 最小证明包支持先行转播，但不降低最终验证要求。
- 将 16 字节短 TxID 限定为网络优化，可避免把前缀碰撞风险带入共识。
- 碰撞时请求完整数据是确定且安全的退避路径。

## Consequences（影响）

- 网络层可基于短 TxID 优化区块同步，但验证层不得依赖短 TxID 做最终判断。
- 节点需要在发现短 TxID 歧义时回退到完整 TxID 请求。
- 在待冻结参数确定前，区块证明包只能作为候选网络协议结构。

## Conception Relationship（与构想关系）

- 补充 `conception/2.共识-端点约定.md`、`conception/附.组队校验.md` 和 `conception/blockchain.md` 中快速转播证明材料的最小字段。
- 不改变完整区块验证必须最终核对完整交易 ID 序列和 CheckRoot 的构想层规则。
