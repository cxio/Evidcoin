# DEC-0504: Script Cost Budget（脚本成本预算）

Status: Proposed

## Context（背景）

Conception 已要求脚本成本分为单输入、单交易、单区块三层，并由确定性成本函数计算。但各 opcode 基础成本、动态成本因子、内存成本、跳转/嵌入计数和区块总成本函数尚未冻结。

## Decision（决策）

建议成本模型：

- 每条指令有 `base_cost`。
- 依据输入字节数、输出字节数、哈希次数、签名验证次数、正则复杂度和脚本引用次数增加动态成本。
- 内存成本按峰值数据栈字节数、实参区字节数、局部域字节数计入。
- 成本函数只依赖脚本字节码和运行时确定数据，不依赖硬件性能。
- 成本超限时交易验证失败。

建议三层上限：

- `MaxInputScriptCost`：限制单输入。
- `MaxTxScriptCost`：限制单交易所有脚本。
- `MaxBlockScriptCost`：限制单区块所有脚本。

建议计数规则：

- `GOTO` 和 `EMBED` 在目标解析成功前先计数。
- 被禁用指令在静态阶段拒绝，不消耗运行成本。
- 公共验证隐式 `END` 后的私有路径不计入公共验证成本。

## Rationale（理由）

静态长度限制不足以约束签名验证、哈希、正则和外部脚本引用的成本。三层预算能防止单输入攻击、单交易攻击和区块级资源耗尽。

## Consequences（影响）

- 成本表冻结后不能随硬件升级随意调整，否则会破坏共识。
- 脚本模板库需要提供成本估算工具。
- 暂不设计按成本提高交易费的协议功能，保持初期简化。

## Open Questions（开放问题）

- 每个 opcode 的具体 `base_cost` 和动态成本公式。
- 区块总成本是否随区块容量逐年增长而增长。
- 正则、模式匹配和随机指令的最坏成本如何上界。
