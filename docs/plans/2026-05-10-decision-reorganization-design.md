# Decision Reorganization Design（决策文档重整设计）

## 背景

`docs/conception` 已完成较大修订，部分原有 `docs/decision` 文档已经被构想层吸收，或与最新构想存在不一致。Decision 目录需要先对现有决策进行合并、删除、重编号和职责边界整理，再新增高优先级补充决策。

## 目标

- 以最新 `docs/conception` 为最高依据，重新整理现有 DEC。
- 允许重新编号、合并和删除旧 DEC。
- 对已由构想层明确的内容，不再保留重复 Decision。
- 先理顺现有 20 篇 DEC，再从新编号之后新增高优先级 DEC。
- 在 `README.md` 中保留旧编号到新编号、合并或吸收状态的迁移索引。

## 重整策略

第一阶段只处理现有 DEC：

- 删除或吸收 `DEC-0001`：PoH 铸凭哈希算法已由构想层明确为单层 `BLAKE3-256`，不再保留“内层算法”或独立哈希结构决策；仅将 `X` 编码、域分隔、碰撞处理等仍需规范化的内容保留在其它 DEC 中。
- 合并同类主题：PoH 参数编码与碰撞边界、通用编码与域标签、全网通告授权根和公钥演化等按主题重新排列。
- 修正过时内容：删除 `-27` Stakes 引用，统一为评参区块自身的 Stakes；修正铸凭哈希长度为 32 字节；修正短引用碰撞规则以匹配最新构想。
- 保留实现相关细节：varint、domain tag、字段宽度、地址编码、ML-DSA 集成、Float 确定性、奖励余数、哈希树边界等仍属于跨实现一致性问题，应保留或合并。

第二阶段新增高优先级 DEC：

- 交易过期边界语义。
- 签名消息规范化编码。
- Coinbase 完整编码与公共服务兑奖槽。
- 原始铸币发行曲线高度边界与取整。
- Credit 31 年过期边界。
- 脚本成本预算与公共/私有执行边界。
- 脚本 Float 扩展语义。
- 区块证明包与区块概要短 TxID 碰撞处理。
- 分叉平局 Hash 算法收敛。

## README 结构

`docs/decision/README.md` 更新为：

- 维护原则。
- 状态枚举。
- 命名规范。
- 当前决策索引，包含编号、标题、主题域、状态和说明。
- 旧 DEC 迁移索引，说明旧编号被保留、合并、删除或被构想层吸收。
- 不再单列的决策清单。

## 验收标准

- `docs/decision` 中 DEC 编号连续且 README 链接有效。
- 旧编号迁移关系清晰可追踪。
- 不再出现 `-27` Stakes 引用。
- 不再出现 PoH “内层/外层哈希”口径。
- 铸凭哈希长度统一为 32 字节。
- 短引用碰撞规则与最新 conception 一致。
