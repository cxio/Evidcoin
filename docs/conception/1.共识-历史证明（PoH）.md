# 共识：历史证明（PoH）

区块链是区块的链表，区块包含了不定数量的交易，如果有一笔交易进入了区块，就相当于该交易成了事实，也称为被 *确认*。

区块是交易的集合，任意节点都可以验证交易然后打包创建，但谁打包的区块才算数呢？这就需要共识，一种机制，来决定谁打包的区块可以进入主链，也即：谁拥有区块的铸造权。


## 基于历史的证明（PoH: Proof of Historical）

交易ID是交易数据的哈希摘要，拥有很强的随机性，如果把交易ID用作一个评选因子，是否就可以获得某种随机的筛选呢？

交易是任何一位用户都可以创建的，拥有普适性，同时，交易ID作为历史数据无法更改，它又拥有确定性。与传统的PoS权益证明不同，交易ID也与财富无关，没有富者越富的逻辑。所有的交易ID都是平等的，唯一增加获选机会的方式就是创建更多的交易。

创建交易有交易费成本，但毫无疑问，这种机制会一定程度鼓励交易。更多的交易和交易费可以充实矿工的收益，这是良性的。


### 哈希塑造

采用数据的哈希序列进行评比可能会出现一种攻击：

*通过向哈希源数据中加入随机的无用数据，即可改变哈希计算的结果，使其趋近于某种想要的目标*。此即：「**哈希塑造**」。

为避免这种攻击，需要对参与哈希计算的因子进行约束：不应当有可塑性，或可塑性极低，或成本高昂。


### 参与因子

#### 概念

- **铸凭交易**：有资格参与铸造评选的交易称为铸凭交易。
- **铸凭哈希**：以各种因子结合计算的哈希称为铸凭哈希，它是铸造竞争的直接对比值。
- **评参区块**：铸造竞争的源数据应当是动态的。我们用动态增长的链末端来表达，比如取末端某个负高度的区块的相关信息。
- **UTXO指纹**：UTXO是「Unspent Transaction Output」的缩写，可以用UTXO集的指纹来获得某种动态的确定性。
- **币权总值**：交易的 `币量*币龄` 称为币权。一个区块收录的交易的币权合计（总值），可以作为一个动态的半确定性因子。

> **注：**
> 币金被交易花费后，其新输出的币龄为零。也即「币权销毁」。
> 币龄按交易实际被收录入区块的时间计算，而非通过交易的时间戳计算。


#### 可塑性分析

*交易ID*是交易数据的哈希摘要，用户可以通过在交易里添加冗余数据来任意塑造交易ID。因此交易ID必须位于末端动态参考位置之前的区域，使得在交易创建时，没有信息可供针对，无法塑造。

*区块ID*的逻辑类似，铸造者也可以往Coinbase交易里填充信息（同时还能自由组织交易序列），因此不能采用。

UTXO集的*指纹*是当前区块链所有UTXO的总结，改变该指纹需要实际创建交易并花费，有交易费成本。**注**：UTXO指纹的计算包含了交易ID，因此其可塑性依然强大。

末端区块的*时间戳*是动态的，但区块创建有严格的时间间隔，因此时间戳没有可塑性。**注**：区块时间戳并非实际存在的字段，而是通过创始块时间戳和高度计算得出。

*铸凭哈希*是最终的计算结果，如果设计可行，铸凭哈希是市场化自由竞争的结果，是否可预期（或塑造）取决于算法本身是否合理。每一个区块都有自己的铸造者（也即铸凭哈希），动态的链末端逻辑可以提供随机的确定性。

**币权总值**由区块收录的全部交易决定，如果要改变币权总值，就需要改变区块所收录的交易。添加新的交易会有交易费成本，而移除交易则有交易费损失，因此币权总值的可塑性很低，成本也较高。


### 规则

- 铸凭交易：有效区间为 `[-10 ~ -80000]` 号区块高度。设计截止时间可提供一种淘汰机制。
- 评参区块：取链末端的 `-9` 号区块。这是一个综合权衡的折衷值，考虑了时间长度（8*6=48 分钟）对参与者的友好性。
- 铸 造 者：取铸凭交易里*首笔输入*的接收者公钥地址。用已花费地址更安全，用户无需为了竞争铸造而公开公钥（签名）。

淘汰机制可以让用户有机会抛弃过往（比如委托了不良的第三方），同时也让攻击者总是需要不断地积累新的资源……

> **注意：**
> 在一个区块形成前，其铸造者可能已经出现在择优池中了，
> 因为一个新区块创建后，它就会作为未来的评参区块被针对，竞争者据此评估自己的资格。


#### 铸造者门槛

为避免刷交易问题，铸造者需要满足一个最低币权门槛：*铸造者（首笔输入）的币权销毁必须 `≥4M` 聪时*。

这是当前的设定，后期可能根据网络发展情况调整（协议级：需要硬升级）。目标：*对普通的交易参与者没有阻碍，但能有效抑制批量刷交易*。


### 铸凭哈希

> **说明：**
> 下面的伪代码类似Go语言语法，但仅用于表意。

算法示意：

```go
Mix := 0x517cc1b727220a95       // 混合常数，增加Bit位复杂性（FxHash 算法常量）
Stakes := 评参区块币权总值      // 聪时数，已存在于区块头内（Stakes字段）
timeStamp := currentBlockTime   // 当前区块时间戳（Unix 毫秒），按区块高度计算而来

X := Bytes(timeStamp * Stakes * Mix) // 转为字节序列

// 铸凭哈希：
// 加入铸造者公钥以增强信息熵并绑定身份。
// pubKey 为铸凭交易首笔输入对应的铸造者公钥，需配合域分隔。
var hashMint []byte = Hash( domainTag || pubKey || 铸凭交易ID || 评参区块:铸凭哈希 || X )
```

评选简单地对比铸凭哈希序列，值小者胜出。

> #### 设计注记
> 实际上无法用签名数据计算铸凭哈希，因为签名数据通常有可塑性问题，
> 即便标准的签名算法是确定性的，只要算法中有自由的随机数，就可能通过定制修改创建可塑性。这会带来类似 PoW 的竞争，失去公平性。

参与铸凭哈希计算的因子都是公开的，没有隐蔽性。这有一个好处：可以让外部观察者分析"理论上有多少优质铸凭交易并未参与铸造竞争"，从而评估网络的状况。

但这也可能带来攻击：分析查找未参与铸造竞争的最优者，找到他们，收买贿赂……从而进行分叉攻击。这有20个区块的时间窗口（2小时），9个有效收买（分叉超9个区块后，评参区块就不同了）。


### 初段规则

区块链最初创建的9个区块没有 `-9` 号评参区块，因此需要一些特别的处理。

涉及两个基本变量：

1. 评参区块高度获取。
2. 交易所在区块的高度的合法性。


#### 评参区块

因为铸造竞争源于交易ID，初期的交易只由区块链的创建者发布，没有攻击者，因此可以采用简单的算法如下：

```go
// 初段：
// 评参区块取创始块即可
// @currentHeight 当前区块高度
if currentHeight < 9 {
    return 0
}
// 后期：正常的取值。
return currentHeight - 9
```


#### 铸凭交易

源于同上没有攻击者的原因，区块创建者不需要塑造交易ID，因此简单地判断即可：

```go
// 初段：
// 交易所在区块高度是否合法。
// @currentHeight 当前区块高度
if currentHeight < 28 {
    return true
}
// 后期：正常的判断
// @txHeight 交易所在区块高度
h := currentHeight - txHeight
return h > 27 && h <= 80000
```

任何合法的交易ID皆可作为铸凭交易参与竞争。第28块之前的参与因子可灵活处理。


#### 百日扩张

基于交易历史的证明要求参与者已经是用户，这就需要把铸造的币金分发出去。除了公共服务可以从外部获取币金之外，对于初期的区块链成长，这里设计为一个百日扩张方案。

- `0号` 区块：*创始区块*。区块链启动。
- `1 - 10号` 区块：*私钥扩张*。创建适量的收益地址，用于之后的交易创建和铸凭交易竞争。
- `11 - 7200号` 区块（30日），*币金积累*。观察情况，保留随时停止区块链运行的可能性。
- `7201 - 24000号` 区块（百日）：*抽奖扩张*。由社区推广活动收集地址，由积累的币金发放奖励，扩展初期铸凭交易规模。

至此，铸币交易（Coinbase）中只有一笔输出，无公共服务奖励。

- `101日 ~`：接受公共服务，启动对外奖励。进入正常的自由市场……

> **注：**
> 百日扩张期间每交易输出项数量应当不超过输入数量的**2**倍，以约束扩张速度。
> 此为共约（非协议），初期的区块铸造者理应能协调一致遵守。



## 铸造者的预选

因为评参区块是链末端 `-9号` 区块，所以一个铸造候选者最多可提前 `8个` 区块时段得知要对比的目标。如果一个节点及时评估并广播自己的铸凭交易（及其凭证），则全网会有充足的时间进行预先沟通。尽量多的参与者加入，可以使尽可能优质的铸凭交易被发掘出来。


### 择优池

在铸造候选者的预先沟通中，各个节点会收集广播出来的铸凭交易，按品质排序放入一个缓存池，这个缓存池就是 **择优池**。择优池实际上是一个池集，因为每一个评参区块都对应一个择优池。

新的铸凭交易加入择优池的逻辑很简单：计算其铸凭哈希，如果比池中最差的一个好，则有序插入并转播，否则忽略。


### 择优凭证

铸造候选者的证明包含如下几项信息：

- 高度：交易实际所在区块高度。用于判断范围合法性，以及检索相关信息验证交易ID。
- 交易ID：参与铸凭哈希计算。
- 铸造者：首笔输入源输出的接收者公钥。同时作为铸凭哈希的输入因子。
- 铸凭哈希：即上面的 `mintHash` 值，简单携带（可被上面相关信息推导计算出来）。
- 签名数据：铸造者对 `mintHash` 的签名，用于证实身份。

最终的铸造者的*择优凭证*会存储在区块的 `Coinbase` 交易中，用于铸造者资格证明。


### 择优池同步

为避免刚上线的优质竞争者带来扰乱（引起分叉），动态更新的择优池需要在各节点间提前确定下来，这就是择优池的同步。

一个新区块在成为评参区块（`-9号`）之前，铸造竞争有如下分段逻辑：

1. **广播收集**：新区块创建后，到它成为 `-7号` 区块前，有**6**个区块时段可以对铸凭交易计算铸凭哈希，广播并优选。
2. **同步优化**：当该区块成为 `-7号` 区块后，择优池的更新结束，进入同步期。耗时**2**个区块时段。
3. **抵达结束**：当该区块成为 `-9号` 区块后，即成为当前待创建区块的*评参区块*。此时其择优池中的候选者已确定。


#### 广播收集

除了接收铸凭交易的广播和评估外，此阶段节点还会彼此沟通择优池状况，以期最优化择优池成员。

广播收集历经6个区块时段，时间裕度36分钟。较长的时间使得在进入同步阶段后，大部分节点的择优池（区块特定）状况应该差异不大。


#### 授权节点约束

择优池大小设计为 `20`，有权同步的节点为择优池中 `后15` 名成员。这基于利益无关性考虑：

*在P2P环境下，时间无法准确约束，如果没有限制，优质的迟到竞争者可以随时把自己加入择优池。这会导致同步工作难以正常结束。*

有了此授权节点约束，如果优质的候选者迟到了，排名靠后的节点没有动力去把它额外补入。而一个中等优质的迟到者也没有动力把自己加到择优池，然后开启新的同步，因为它基本不可能成为铸造者。

> **注：**
> 一个授权节点只有一次同步的权力。


#### 同步流程

**约定**：每个同步者提供的择优池称为*目标池*，接收者自己的择优池称为*本地池*。

- **裁判池**：创建一个本地池的副本，合并目标池，即为裁判池。判断对端是否在裁判池里的后段15位中，如果不在，则拒绝同步。否则缓存目标池（单独形式暂存）。
- **预合并**：同步时间截止后，合并所有暂存的目标池，取合法范围（后段15位）内的成员，即为授权节点集。
- **终合并**：对授权节点集成员的目标池进行合并，即得到最终的择优池。

对于一个新上线的节点，其本地池为空，但这不影响裁判池的创建（此时裁判池就是对端的目标池）。

这是一种P2P环境下的概略性同步，不是拥有唯一性的精确约束。但设计通过足够长的时间宽容度来尽可能优化结果，不过效果有待验证。

如果最终的择优池没有唯一性，会导致分叉。这由后续的分叉竞争机制来解决，以最终收敛到一个唯一的主链。


### 附：铸造者来源验证

用户（铸造竞争者）已提供交易所在区块高度、交易ID等信息。

> **前提：**
> 区块头链是验证的终点，每个客户端都持有区块头链。


#### 交易ID的合法性验证

**检索**：从交易ID检索交易头信息，其中包含：

1. 输入段：首领输入、剩余输入段哈希。用于计算输入段根哈希。
2. 输出段根哈希。
3. 交易时间戳。
4. 交易ID在区块内的序位（3字节序号）。
5. 默克尔哈希验证路径（从交易ID到区块头的验证路径）。

**验证**：根据上面的信息验证交易ID是否匹配。

- 从用户提供的区块高度验证是否在合法范围内（`[-80000, -28]`）。
- 从 `1-3` 的信息计算交易头的哈希值，验证其与交易ID匹配。
- 从区块高度检索区块头链中的区块头信息，提取其中的 `CheckRoot`，同时检索对应的 `UTXO/UTCO` 集合指纹值。
- 从 `4-5` 的信息，结合默克尔哈希验证路径，核实交易ID确实属于该区块（`CheckRoot`）。


#### 铸造者身份验证

- 根据首领输入（年度+交易ID+输出序位）检索其来源输出项数据，以及到所在交易ID的哈希验证路径。
- 对比输出项数据中的哈希公钥，是否与择优凭证中的公钥匹配。
- 提取输出项数据里的币金量，结合币龄（按区块高度计算），验证其币权销毁量是否满足门槛要求。
- 计算输出项数据的哈希，结合哈希验证路径，核实所得数据确实属于该交易（交易ID匹配）。


#### 优化策略

对于上面铸造者来源的相关证明信息，实际上都可以由铸造竞争者自己提供。因为它们都可以被验证。

这样就可以免于向公共服务节点检索，减少对公共服务的压力，同时也能加快验证速度。



## 设计参数

- 铸凭交易的区块有效范围：`[-80000, -28]`（约11个月）。
- 评参区块为 `-9号` 区块，其铸凭哈希参与当前区块的铸凭哈希计算。
- `-27号` 区块的币权销毁值用于铸凭哈希的计算。
- 择优池容量为 `20名` 候选者，内部按铸凭哈希字节序列从小到大排列（值小者优）。
- 择优池中排序在前5名之后的 `15位` 候选者有权发起择优池同步。
