- **职责：** 定义 UTXO（未花费币金）/ UTCO（未转移凭信）集的状态指纹结构——五层宽成员树、分层与排序、末端叶子前像、空根、FlagOutputs 位语义、UTCO 过期处理、链式约束与缓存边界。

## 规格正文

### 1. 集合定义〔附.交易.md#附utxoutco-集合〕

- **UTXO** 集：所有已确认交易的未花费币金输出集合。
- **UTCO** 集：所有已确认交易的未转移凭信输出集合。
- 二者确定于**上一个区块**完成态（未确认交易的输出不入集——可能被替换或过期，亦是组队校验的交易独立性要求）。
- 自定义类输出不进入 UTXO/UTCO（见第 06、07 章）；存证不可作输入源，不参与状态集的可花费成员。
- UTXO 与 UTCO 采用**相同结构与计算方式**，但作为各自独立服务运行（请求目标币金/凭信很明确）。

### 2. 五层宽成员状态树〔附.组队校验.md + DEC-0201〕

宽成员哈希校验树，共**五层**分级（减少每次状态改变的重算量）：

| 层 | 分级依据 | 说明 |
|----|----------|------|
| 顶层 | 年度 | 交易时间戳对应 UTC 自然年（见第 01、03 章），无限增长但粒度足够大 |
| 二层 | TxID 字节索引 `[7]` | 0-based，取第 8 个字节值分组 |
| 三层 | TxID 字节索引 `[11]` | 0-based，取第 12 个字节值分组 |
| 四层 | TxID 字节索引 `[15]` | 0-based，取第 16 个字节值分组 |
| 末端叶 | 完整 TxID 状态 | `Hash384(TxID || FlagOutputs)`（见 §3） |

> 采用 0-based `[7,11,15]`（而非旧案 `[8,13,18]` 或低位 `[0,1,2]`）字节索引分层，以获得更好随机性、避免 ID 塑造者影响，且均落在交易输入项最短长度（16+字节）覆盖范围内，可有效检索目标。
>
> **加注（索引口径）：** conception 图解将三级分层字节记为 `[7,11,15]`；DEC-0201 正文表述为「按 TxID 字节索引 `[7,11,15]` 分入三级宽成员节点」。二者一致——三级分层分别取 TxID 第 8、12、16 个字节值，末端按完整 TxID 字典序排列。本章以 0-based 三字节分层口径为准。

- 该树**不**直接套通用二叉证明格式（第 04 章 §3.5 已指明）；分支节点按 `tree.branch` 域标签编码，末端叶 SHA3-384。

### 3. 末端叶子前像〔附.组队校验.md + DEC-0201〕

conception 给出叶子前像 `Hash384(TxID || FlagOutputs)`，其中：

```go
FlagOutputs: {
    Count     int      // 有效标记位数量，减至零时该节点即可移除
    FlagBytes []byte   // 每位对应一个输出项：1=未花费/未转出，0=已花费/已转出或无效
}
```

DEC-0201 将其细化冻结为：

```text
StateLeaf = SHA3-384( DomainTag("utxo.leaf" 或 "utco.leaf") || TxID || Count || FlagBytes )
```

- **加注（以 conception 为准 + DEC 细化）：** conception 概念式记 `Hash384(TxID || FlagOutputs)`；DEC-0201 明确前像顺序为 `TxID || Count || FlagBytes` 并前置 `utxo.leaf`/`utco.leaf` 域标签。二者无冲突——DEC 是 conception `FlagOutputs` 结构的字节级展开，本章采用 DEC-0201 的精确前像。
- `Count` **必须保留**在叶子前像中，表示该 TxID 对应的**有效输出数量**，而非 `FlagBytes` 字节数。

### 4. FlagOutputs 位语义〔DEC-0201〕

- `FlagBytes` 第 `i` 位对应输出序位 `i`。
- **位序：每字节低位优先**（bit0 对应较小输出序位）。
- `1` 表示未花费/未转出，`0` 表示已花费/已转出或无效。
- `Count` 表示有效输出数量，减至零时该末端节点即可移除。
- 尾部未使用 bit 必须为 `0`。

### 5. 分层排序与空根〔DEC-0201 + 第 02 章〕

- 顶层年度按**数值升序**排列。
- 年度内按 TxID 字节 `[7,11,15]` 分入三级宽成员节点。
- 同一末端分组内按**完整 TxID 字典序**排列（与第 06 章短引用碰撞「TxID 排序首个匹配」一致）。
- 空年度、空分组**不编码**；整棵空状态树使用专用空根：
  - UTXO 空根：`SHA3-384( DomainTag("utxo.empty") )`。
  - UTCO 空根：`SHA3-384( DomainTag("utco.empty") )`。
- 空根域标签 `utxo.empty`/`utco.empty` 与第 02 章域标签全集（第 13、14 项）一致；第 04 章 §1「空根」亦引向本章。

### 6. UTCO 过期处理〔DEC-0201 + 第 07 章〕

- Credit 过期条件 `age > 31 × 87661`（见第 07 章 §5）；过期时对应状态位失效。
- 若同一 TxID 下仍存在其它未转出且未过期 Credit → 保留该 UTCO 叶并更新状态位（`Count` 递减）。
- 若同一 TxID 下已无任何有效 Credit → 从 UTCO 状态树**删除该叶**。

### 7. 链式约束（三路耦合）〔附.组队校验.md#utxo-集指纹的链式约束〕

- UTXORoot/UTCORoot 取**前一区块完成后**的状态集（计算时间充裕；见第 05 章 CheckRoot）。
- **三路耦合保护：** UTXO 花费约束 + UTCO 转移约束 + 区块 ID 链式约束，共同锁定区块链历史。
- **逆向推导：** 当前 UTXO 集（上一区块结果集）减去上一区块新交易输出与 Coinbase 铸币、加回上一区块输入项 = 上一区块的当前 UTXO 集；其指纹应与上一区块 UTXO 指纹相同。如此循环迭代，可从最新 UTXO 集逆向验证至任意历史位置（UTCO 同理）。
- 由此 UTXO/UTCO 指纹与区块 ID 链式绑定，从不同侧面共同锁定历史。

### 8. 缓存边界〔DEC-0201 + 附.组队校验.md〕

- **状态位集合参与指纹**；输出详情（`map[int64]Outputs` 等）**不参与指纹**，仅为同形分层的检索优化（缓存集，校验组组内公共服务）。
- 逆向推导验证只依赖状态位集合，不依赖缓存详情。
- 缓存集以 TxID 前 8 字节为键，附带防碰撞集合（正式集未命中则查防碰撞集）；其合法性由另外的验证过程保证（见第 13 章组队校验）。
- 查询服务（Blockqs，第 15 章）须能区分「状态位证明」与「输出详情证明」的边界。

## 边界与限制

- 未确认交易输出不入集；自定义类输出不入集；存证不作可花费成员。
- 分层固定取 TxID 字节 `[7,11,15]`；末端按完整 TxID 字典序。
- 叶子前像必须含 `Count`（有效输出数，非字节数）；位序低位优先；尾部未用 bit 为 0。
- 空年度/空分组不编码；整棵空树用专用空根域标签。
- UTCO 叶在同 TxID 无有效 Credit 时删除。
- 状态根取前一区块完成态，不取当前区块。

## 对 Plan 的约束

1. `internal/utxo`、`internal/utco` 各自实现五层宽成员状态树（年度层 + TxID 0-based `[7]`/`[11]`/`[15]` 三层 + 末端完整 TxID 叶子层），分支用 `tree.branch` 域、末端叶用 `utxo.leaf`/`utco.leaf` 域 + SHA3-384。
2. 叶子前像固定 `TxID || Count || FlagBytes`，`Count` 为有效输出数；FlagBytes 位序低位优先、尾部 0、1=有效。
3. 空树根用 `utxo.empty`/`utco.empty` 域标签哈希（与第 02 章一致）。
4. UTCO 过期处理：位失效 → 同 TxID 无有效 Credit 时删叶（与第 07 章 `age > 31×87661` 联动）。
5. 状态根供第 05 章 CheckRoot，取前一区块完成态；实现逆向推导验证（仅依赖状态位）。
6. 缓存集（输出详情）与指纹分离，不参与状态根；查询边界区分状态位证明与详情证明。
