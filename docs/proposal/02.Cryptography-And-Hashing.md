## 规格正文

### 1. 域标签编码〔DEC-0002〕

- 域标签编码为 ASCII 字符串：`DomainTag(name) = "Evidcoin/v1/" || name || 0x00`。
- 域标签必须作为哈希前像**首段**，不参与用户可控字段的长度解释。
- 作为 ASCII 字符串常量直接进入前像，不压缩为整数编号。
- 同一算法不同用途必须使用不同标签，即使输入结构当前不可混淆。
- 版本号位于标签头部（`v1`），用于未来整体迁移到 `Evidcoin/v2/...`；当前所有标签均为 `v1`。

### 3. 算法 profile〔blockchain.md#哈希策略 + DEC-0002〕

| 用途 | 算法 | 输出 | 备注 |
|------|------|------|------|
| 区块头 | SHA3-384 | 48B | 兼顾量子安全与数据量 |
| 交易头（TxID） | SHA3-384 | 48B | 与区块头一致 |
| CheckRoot | SHA3-384 | 48B | `Hash384(TreeRoot \|\| UTXORoot \|\| UTCORoot)`（详见第 05 章） |
| 通用树枝 | BLAKE3-256 | 32B | 多哈希场景，提速省内存 |
| 通用树叶（默认） | SHA3-384 | 48B | 与树枝不同算法（除非另有说明） |
| 附件完整指纹 | SHA3-512 | 64B | 超长期安全；与片组哈希双哈希耦合 |
| UTXO/UTCO 末端叶 | SHA3-384 | 48B | 数据摘要 |
| UTXO/UTCO 空状态树根 | BLAKE3-256 | 32B | 与非空状态树根同宽 |
| 公钥哈希 | SHA3-256(BLAKE2b-512(...)) | 32B | 约 128 位量子安全（空间/安全权衡） |
| 铸凭哈希 | BLAKE3-256 | 32B | 大量参与者，关注速度 |

- BLAKE3 **不使用** keyed mode；所有用途统一为普通 hash 加域标签前缀，跨用途隔离完全依赖域标签〔DEC-0002〕。

### 4. 附件片组哈希树例外〔DEC-0002〕

附件片组哈希树（leaf 与 branch 皆 BLAKE3-256）**不前置任何域标签**——这是全局"前像首段必须为域标签"规则的**唯一例外**：

- 叶子：`BLAKE3-256(2-byte seq || BLAKE3-256(piece_data))`（34 字节预像 = 2 字节顺序号 + 32 字节分片哈希）。
- 分支：`BLAKE3-256(left || right)`。
- 理由：面向通用文件分享场景，便于外部数据网络（Depots）直接复用普通文件分片验证工具。
- 后果：片组哈希值与协议内其它树根虽同算法，但因无域标签而属不同名字空间。

> 树结构细节见第 04 章；附件本身见第 07 章；Depots 服务见第 15 章。

### 5. 公钥哈希〔附.交易.md + DEC-0104〕

- **单签：** `address.single` 域；`SHA3-256( BLAKE2b-512(pubKeyBytes) )`，输出 32B。
- **多签（复合公钥哈希）：** `address.multi` 域；流程：
  0. 各公钥计算初级哈希 `BaseH = BLAKE3-256(pubKeyBytes)`。
  1. N 个初级哈希按**字典序**排序后串联：`BaseHAll = Concat(Sort(BaseH...))`。
  2. 前置 `m || n` 两字节配比，计算 `PKHmix = SHA3-256( BLAKE2b-512( <m/n> || BaseHAll ) )`。
- 多签约束：`m` 与 `n` 均不得为 0，且 `m <= n`；不得含重复公钥（重复时地址构造与见证验证均非法）〔DEC-0104〕。
- 单签与复合公钥哈希在外观上无区别（隐私安全），但验证逻辑不同；判别由见证信息指明（详见第 08 章）。

> **三套多签排序规则**（见证容器字典序 / 签名消息提供顺序 / 地址派生字典序）的对照锚定见第 08 章；本章只承载"地址派生字典序"。

### 6. 地址编码〔附.交易.md + DEC-0104〕

- 地址文本：`prefix || Base58(pubKeyHash || checksum)`。
- 校验码：`checksum = last4( SHA2-256( SHA2-256( prefix || pubKeyHash ) ) )`。
- Base58 使用 **Bitcoin 字母表**。
- `prefix` **参与**校验码计算，但**不进入** Base58 负载。
- 网络前缀：主网 `Cx`、测试网 `Tx`、开发网 `Dx`（三网必须不同，不可混用）。

### 7. ML-DSA-65 profile〔DEC-0104〕

- 使用 **ML-DSA-65**。
- 固定使用 `github.com/cloudflare/circl` 的 ML-DSA-65 实现 profile。
- 公钥、私钥、签名序列化采用 `circl` 的 canonical byte encoding。
- 签名验证输入为第 08 章（DEC-0102）定义的签名消息字节序列。

> **注（A-2 取舍加注）：** ML-DSA 锁定 `cloudflare/circl`。本提案以 **DEC-0104（circl）为准**，因 conception 未直接固定实现库、DEC 已冻结 profile。标准库迁移仅作为未来兼容观察项，不属于当前全局待决项。

## 边界与限制

- 任何冻结后的哈希前像都必须列明域标签（附件片组哈希树例外）。
- 历史版本升级应通过 `Evidcoin/vN` 整体隔离。
- 公钥哈希为 32B（量子安全最薄弱环节，依赖抗量子签名补强）。
- 多签 `m/n` 配比为 1+1 两字节，最大规模 `255/255`。
