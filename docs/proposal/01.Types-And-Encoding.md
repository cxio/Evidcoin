## 规格正文

### 1. 整数编码

#### 1.1 固定宽度整数（大端序）〔DEC-0001〕

固定宽度整数统一使用**大端序**。适用于 `uint16`、`uint32`、`uint64`、`int64` 及固定宽度脚本附参。

#### 1.2 无符号变长整数 ULEB128〔DEC-0001〕

- 无符号变长整数使用 **ULEB128**（等同 Protocol Buffers wire format 的 unsigned varint）：每字节低 7 位承载数据，高位为续位，低位组先出现。
- 本提案中统一记为 `varint(x)`。
- **最短编码强制**：`0` 编码为 `0x00`；任何带冗余高位零组的编码非法。
- 协议字段**不使用**有符号变长整数；需要有符号语义时采用定宽（如 `int64`）按大端序编码。

> **注（时间戳特例）：** 脚本值类型 `Time`（值指令 `DATE`，conception `Instruction/1.值指令.md`）在脚本字面量层面以"有符号变长整数"承载 UNIX 毫秒时间戳。这属于脚本字面量编码，不属于协议字段编码；协议字段的时间戳（如交易头 `Timestamp`）按定宽 `int64` 大端编码（见 1.4 白名单）。

#### 1.3 字节序列〔DEC-0001〕

- 默认编码：`varint(length) || bytes`。
- 固定长度字段不带长度前缀。
- 受限长度字段先按编码长度检查，再按语义长度检查；超过 conception 限制者非法。

#### 1.4 定宽字段白名单（闭集）〔DEC-0001〕

协议字段中未显式声明定宽的整数，统一按 `varint`（ULEB128）编码。当前已明确的定宽字段白名单：

| 字段 | 类型/宽度 |
|------|-----------|
| 区块头 `Version` | uint32 |
| 区块头 `Height` | uint32 |
| 区块头 `Stakes` | uint64 |
| 交易头 `Version` | uint16 |
| 交易头 `Timestamp` | int64 |
| 哈希字段（`PrevBlock`、`CheckRoot`、`YearBlock`、`TxID` 等） | 各自哈希算法的固定字节数（见第 02 章） |
| 脚本附参中按 opcode 文档声明的定宽位 | 按 opcode 文档 |

> 白名单为**闭集**；后续若需新增定宽字段，必须在引入该字段的 DEC 中显式声明并同步本白名单（见第 05、06、08 章涉及的字段）。

#### 1.5 年度字段〔DEC-0001〕

年度字段使用 **UTC 自然年份数值**（如 `2025`），不使用相对创世的偏移量。适用于交易输入项短引用、UTXO/UTCO 状态指纹分层等所有按年度划分的协议字段（见第 06、09 章）。

### 2. 基础值类型

下列为脚本与协议共用的基础值类型（conception `Instruction/1.值指令.md`）：

| 类型 | 说明 | 范围/宽度 |
|------|------|-----------|
| `Bool` | 布尔（由 `TRUE`/`FALSE` 指令码本身表达） | true / false |
| `Byte` | 字节（uint8 别名） | `[0, 255]` |
| `Rune` | Unicode 码点（uint32） | `[0, 0x10FFFF]`；仅用于码点 > 0xFF 的字符，≤0xFF 强制用 `Byte` |
| `Int` | 整数（varint 承载于脚本字面量） | `[-(1<<63), 1<<63 - 1]` |
| `BigInt` | 大整数（`big.Int`） | 绝对值最多 127 字节（见 §3） |
| `Float` | 浮点（float64，定宽 8 字节） | 不接受明文 NaN/Inf 输入 |
| `String` | 字符串（UTF-8） | 长度前缀为 `varint` |
| `Bytes` | 字节数据 `[]byte` | 长度前缀为 `varint` |

> **复合/特殊类型**（值集、`Dict`、`RegExp`、`Time`、`Script` 引用、`VALUE` 等）属脚本系统范畴，详见第 10 章；本章仅锚定其中作为编码原语的基础值类型。
>
> **类型提升**（`Byte ⇒ Rune ⇒ Int ⇒ BigInt` / `⇒ Float`）在运行时发生，详见第 10 章。

### 3. BigInt 二进制序列化〔DEC-0001〕

在哈希与签名输入中，`BigInt` 按下列字节布局序列化（与值指令 `BigInt` 的"符号位+长度附参"布局一致，避免双重规则）：

```text
BigIntBytes = slen || magnitude
```

- `slen`（1 字节）：bit7 为符号位（`0` 正、`1` 负），低 7 位为 `magnitude` 字节长度（`0–127`）。
- `magnitude`：绝对值字节序列，**大端无符号**表示。
- `magnitude` 实际长度必须与 `slen` 低 7 位严格一致；超过 `127` 字节非法。
- 零值必须编码为 `slen=0x00` 且 `magnitude` 为空；非零值 `magnitude` 首字节不得为 `0x00`（最短大端）。
- 长度为 `0` 时符号位必须为 `0`（禁止负零编码）。

### 4. 地址文本表示（引向第 02 章）

公钥哈希为 `[32]byte`（算法见第 02 章），其可读文本形式采用 Base58（含识别前缀与 4 字节校验码）。地址编/解码细节与公钥哈希算法见第 02 章 §地址编码；本章仅声明：地址是 32 字节公钥哈希的可逆文本表示。〔来源：附.交易.md「附：公钥哈希的地址编码」〕

## 边界与限制

- 解码器必须**拒绝**非最短 varint，而非容忍后重编码。
- `BigInt` 绝对值上限 127 字节。
- 定宽字段白名单为闭集，禁止隐式新增。
- 所有参与哈希或签名的结构必须使用本章规范编码，否则将导致 TxID/BlockID 不唯一。

## 单位体系（C-8，已裁决，本章承载）

> C-8 原为「待决问题」（chx / Bi / 毫币口径混用），现已由作者裁决，落入正文。

货币单位口径（作者裁决）：

| 单位 | 关系 | 角色 |
|------|------|------|
| `chx` | 最小单位（整数承载单位） | 币金最小不可分单位，金额一律以 `chx` 整数表达与运算 |
| `Bi` | `1 Bi = 10^8 chx` | 人类可读币单位，`1 Bi` 即「1 币」 |

- **链上一切金额（铸币、交易费、销毁、奖励、UTXO 输出）均以 `chx` 整数承载与运算**，取整、余数承接等规则在 `chx` 粒度执行（见第 14 章）。
- `Bi`（= 币）仅为展示/换算单位；conception 文本中的「毫币」为口语展示别名，不作为协议承载单位。
- 与 conception `4.激励机制.md` 一致：`300_000_000 chx/块 = 3 币/块`、`1 币 = 10^8 chx`。
- 第 03 章、第 14 章对本条仅作**引用**，不重复承载，避免两处矛盾。
