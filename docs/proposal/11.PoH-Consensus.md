## 概述

- **架构位置：** Layer 4 共识层，对应代码包 `internal/consensus`。
- **职责：** 定义铸造资格（铸凭交易）的判定、铸凭哈希计算、择优池与择优凭证、择优池同步、铸造者身份验证、创世与初段窗口规则。**不**承载分叉选择与端点约定（见第 12 章）。
- **依赖：** 依赖第 02 章哈希 profile/域标签、第 03 章常量、第 04 章哈希树与验证路径、第 05 章区块头与 `Stakes`、第 06 章交易头与 Coinbase、第 08 章签名；被第 12（分叉）、第 13（组队校验）引用。

> PoH 的核心思想：铸造权不依赖算力或财富，而依赖**历史交易 ID**——所有交易 ID 平等，唯一增加获选机会的方式是创建更多交易。参与铸凭哈希计算的因子均为**末端动态参考位置之前**的不可塑造数据，以抵御「哈希塑造」攻击。

## 规格正文

### 1. 参与因子与有效区间〔1.PoH#参与因子 / #规则 + DEC-0301〕

| 因子 | 取值 | 抗塑造说明 |
|------|------|-----------|
| 铸凭交易 | 区块高度区间 `[-80000, -240]`（约 11 个月，正常期） | 交易 ID 必须早于末端动态参考位之前，创建时无信息可针对 |
| 评参区块 | 链末端 `-8` 号区块，取其铸凭哈希 | 出块间隔固定（6min），铸凭哈希为市场化竞争结果 |
| 币权销毁 | 链末端 `-32` 号区块的区块头 `Stakes`（聪时，见第 05 章 §3、第 03 章 B-5） | 与评参区块相距较远，抑制铸造者塑造币权动机；改变成本高 |
| 铸造者 | 铸凭交易头 `MintPKHash`，或首笔输入花费者公钥哈希（`LeadPKHash`） | 绑定身份，增强信息熵 |

- 正常期铸凭交易高度判定：`h := currentHeight - txHeight; return h > 239 && h <= 80000`〔DEC-0302〕。
- 淘汰机制：`-80000` 截止使用户可抛弃过往委托、迫使攻击者持续积累新资源；`-240`（1 天）下限阻止低成本交易 ID 塑造。
- `-32` 而非评参区块取币权：若用评参区块值，塑造将成为仅受成本制约的正常可选项〔1.PoH#设计注记〕。

### 2. 铸凭哈希〔1.PoH#铸凭哈希 + DEC-0301〕

铸凭哈希采用**两阶段**算法（字段顺序由 DEC-0301 冻结）：

```text
第一阶段：ChallengeSeed = BLAKE3-256( MintPubKey || MintTxID || Stakes || RefMintHash || X )
          （纯 BLAKE3-256，无域标签）

第二阶段：[hashList, solution, nonce] = equix.Solve(ChallengeSeed)
          要求：nonce ≥ 当前待铸区块高度，solution 索引严格升序

最终哈希：MintHash = BLAKE3-256( DomainTag("mint.hash") || hashList[0] || hashList[1] || ... )
```

| 字段 | 类型/宽度 | 说明 |
|------|-----------|------|
| `MintPubKey` | canonical bytes | 铸造者公钥（`MintPKHash` 或 `LeadPKHash` 的源公钥） |
| `MintTxID` | `[48]byte` | 铸凭交易完整 48 字节 TxID |
| `Stakes` | `uint64`（大端） | `-32` 号区块头币权销毁值（聪时） |
| `RefMintHash` | `[32]byte` | 评参区块 Coinbase 记录的铸凭哈希；创世块/初段无 `Minter` 时取全零 32 字节〔DEC-0301、DEC-0302〕 |
| `X` | bytes | `X = BE(minimal_unsigned(BlockHeight * Mix))`，`Mix = 0x517cc1b727220a95` |

- 域标签 `mint.hash`，哈希算法 **BLAKE3-256**（铸凭哈希用途，见第 02 章；大量参与者场景下兼顾速度与信息熵）。
- `X` 用无损大整数最短编码，避免定宽溢出。
- **择优对比：** 铸造者以四级升序对比：**Nonce 升序**（值小者胜）→ 同 Nonce 下 MintHash 字节序升序 → 再按完整 TxID 升序 → 再按公钥字节升序〔DEC-0301〕。
- 不可用签名数据计算铸凭哈希以隐藏信息：签名通常有可塑性，引入自由随机数将退化为 PoW 式竞争，失去公平性〔1.PoH#设计注记〕。

### 3. 铸造者身份规则〔1.PoH#规则 + DEC-0301〕

- 铸凭交易头**含** `MintPKHash`：`MintPubKey` 的公钥哈希必须等于 `MintPKHash`，但不要求该公钥参与输入根。
- 铸凭交易头**不含** `MintPKHash`：`MintPubKey` 的公钥哈希作为 `LeadPKHash`，必须参与输入根验证 `BLAKE3-256(ListHash || LeadPKHash)`（见第 04 章 §3.2）。
- Coinbase 无输入项，无 `LeadPKHash`；只要 Coinbase 头设置了 `MintPKHash` 且为已确认交易，即可作为铸凭交易参与竞争〔DEC-0301、DEC-0302〕。
- 铸造身份（公钥哈希）与铸凭者（收益地址）解耦：交易可自由设置 `MintPKHash`，降低大平台对铸造的控制力〔附.组队校验#铸造者、4.激励机制〕。

### 4. 择优凭证（MintProof）〔1.PoH#择优凭证 + DEC-0301〕

`MintProof` 字段顺序（冻结）：

| 序 | 字段 | 类型/宽度 | 说明 |
|----|------|-----------|------|
| 1 | `TxHeight` | `uint32` | 铸凭交易实际所在区块高度 |
| 2 | `TxID` | `[48]byte` | 铸凭交易 ID |
| 3 | `Nonce` | `uint64` | Equi-X 求解所得 nonce（须 ≥ 当前待铸区块高度） |
| 4 | `Solution` | bytes | Equi-X 解（solution 字节序列） |
| 5 | `MintPubKey` | bytes | 铸造者公钥（验证身份与签名） |
| 6 | `MintHash` | `[32]byte` | 铸凭哈希值本身（可推导，携带便于检索/预筛选） |
| 7 | `Signature` | bytes | 铸造者对 `MintHash` 的签名 |

- `MintHash` 置于签名前以便检索/预筛选；但签名验证仍以重新计算的铸凭哈希为准〔DEC-0301〕。
- 最终铸造者的 `MintProof` 存储于区块 Coinbase 交易中，参与 TxID 计算（见第 06、14 章）。
- 凭证中的签名是**铸造资格证明**，不是输入项花费签名，不属于见证剪枝范畴（见第 08 章）〔1.PoH#择优凭证〕。

### 5. 择优池与同步〔1.PoH#择优池 / #择优池同步〕

- **择优池容量：** 20 名候选者，按 **Nonce → MintHash → TxID → PubKey 四级升序**排列（值小者优）〔1.PoH 设计参数、第 03 章常量、DEC-0301〕。
- **预选窗口：** 评参区块为 `-8` 号，候选者最多提前 7 个区块时段得知对比目标。
- **同步分段：** 新区块创建后到 `-6` 号区块前的 **5** 个区块时段为「广播收集」（时间裕度 30min）；成为 `-6` 号后进入 **2** 个区块时段的「同步优化」；成为 `-8` 号即定型为评参区块。
- **授权节点约束：** 仅择优池中**后 15 名**成员有权发起同步；每个授权节点仅一次同步权。基于利益无关性，抑制优质迟到者强行加入引发的同步无法收敛。
- **同步流程：** 裁判池（本地池副本 + 目标池合并，判断对端是否在后 15 位）→ 预合并（截止后合并暂存目标池，取后 15 位为授权节点集）→ 终合并（合并授权节点集成员目标池得最终择优池）。新上线节点本地池为空不影响裁判池创建。
- 这是 P2P 概略性同步而非唯一性精确约束；若最终择优池无唯一性将导致分叉，由第 12 章分叉竞争收敛。

### 6. 铸造者验证（三段）〔1.PoH#附：铸造者验证〕

> 前提：区块头链是验证终点，每个客户端持有区块头链。铸造竞争者除 `MintProof` 外还需提供：TxID 到 `TreeRoot` 的默克尔验证路径（叶子含 3 字节前置序号）；若铸凭交易未设 `MintPKHash`，需提供 `ListHash` 以计算输入根。

1. **交易 ID 是否合法：** 验证高度在 `[-80000, -240]`；从 `MintPubKey` 算公钥哈希；按检索的 `MintPKHash` 是否为空区分身份（空则作 `LeadPKHash` 参与输入根，可先验证输入根）；结合检索的交易头字段重算交易头哈希，验证与 `MintProof.TxID` 匹配。
2. **是否属于目标区块：** 按高度从区块头链取 `CheckRoot`，结合目标区块 UTXO/UTCO 指纹与默克尔验证路径核实交易 ID 属于该区块（`CheckRoot` 匹配，见第 05 章 §2）。
3. **铸造者身份：** 重算 `mintHash` 与 `MintProof.MintHash` 比对；验证对 `mintHash` 的签名有效。

- 年初回退检索：高度在真实年初 1 天内、当年度检索无果时，可年度减一再检索一次（区块不收录未来交易，仅需考虑年初回退；外部服务使用真实年度）〔1.PoH#信息检索〕。

### 7. 创世与初段窗口〔1.PoH#初段规则 + DEC-0302〕

- **创世工件**（客户端硬编码，发布后不可变）：创世区块头完整编码、创世 Coinbase 完整交易体、铸造者对 Coinbase 的签名、铸造者对 `CheckRoot` 的签名、创世声明 `FreeData`。双形式发布：`genesis.bin`（canonical 二进制，权威共识形式）+ `genesis.json`（人工审阅，不参与共识）〔DEC-0302〕。
- 创世 Coinbase 的 `Minter` 省略；创世块 `MintHash` 定义为 32 字节全零，仅用于 #1~#7 评参区块铸凭哈希引用语义，不表示有效择优凭证〔DEC-0302〕。
- **初段评参区块高度：** `currentHeight < 8` 取 `0`（创世块）；`currentHeight >= 8` 取 `currentHeight - 8`〔1.PoH#初段规则、DEC-0302〕。
- **初段铸凭交易高度放宽：** `currentHeight < 480` 时 `return txHeight < currentHeight`（仍须引用已确认交易）；`currentHeight >= 480` 用正常 `h > 239 && h <= 80000`。放宽避免进入 `currentHeight >= 240` 后只有第 240 号区块交易满足正常范围〔DEC-0302〕。
- **#1 / #2 规则：** #1 由创世 `MintPKHash` 铸造，可含花费创世输出的普通交易；#2 起允许基于已确认初段交易形成竞争。#1/#2 特殊处理不得泄漏到正常高度逻辑〔DEC-0302〕。
- **Coinbase 铸凭资格：** 初段从 #2 起，已确认 Coinbase 与普通交易都可作为铸凭交易；当前待铸区块内的交易不得作为当前区块的铸凭交易〔DEC-0302〕。

### 8. 围观者参与〔附.组队校验#围观者参与〕

- 校验组允许不参与校验工作的节点（围观者）加入择优池竞争成为铸造候选者。只要围观者参与择优流程即可能成为铸造者，无法也无需阻止。
- 围观者刚上线可能缺乏评估公共受奖地址的信息，管理层会提供 Coinbase 所需的公共服务受奖地址与兑奖槽标记（推荐性，铸造者可不接受，见第 13、14 章）。

## 边界与限制

- 本章只承载铸造资格与择优；分叉竞争、端点出块时序在第 12 章。
- 铸凭哈希因子全部为公开数据（无隐蔽性）；这便于评估网络状况，但也带来收买未参与最优者发起分叉攻击的风险（窗口分析见第 12 章）。
- 创世 `MintHash` 全零仅用于缺省 `Minter` 引用语义，不得当作有效凭证参与正常评选。
- 铸凭交易必须为**已确认**交易；当前待铸区块内交易不得自引用为铸凭交易。

## 待决问题

- **C-9 创世具体参数（与第 05 章协调）：** 创世时间戳与 mainnet `Genesis-ID`（创世 BlockID）尚未冻结。本章承载创世**工件结构**与初段窗口规则（DEC-0302 已定），但 `genesis.bin` 的具体字节取值依赖 C-9 数值裁决；裁决前相关 Plan 任务（创世硬编码、初段评参引用）阻塞于占位值。

## 对 Plan 的约束

1. `internal/consensus` 实现铸凭哈希采用两阶段算法：先以 `BLAKE3-256(MintPubKey || MintTxID || Stakes(BE) || RefMintHash || X)`（无域标签）得到 `ChallengeSeed`，再用 Equi-X 求解得到 `hashList`/`solution`/`nonce`，最终 `MintHash = BLAKE3-256(mint.hash 域 || hashList 拼接)`；`X` 用无损大整数最短编码，且仅由 `BlockHeight × Mix` 决定，与 `Stakes` 无关。
2. `MintProof` 按 §4 七字段顺序编解码；择优对比按 `Nonce → MintHash → TxID → PubKey` 四级升序。
3. 铸造者身份按 §3 区分 `MintPKHash`/`LeadPKHash` 两路；Coinbase 须显式 `MintPKHash` 方可参与。
4. 择优池容量 20、后 15 名授权同步、三段同步流程按 §5 实现；同步为概略性，非唯一性约束。
5. 铸造者验证按 §6 三段实现，含年初回退检索。
6. 初段窗口按 §7 实现，覆盖高度 0/1/2/7/8/239/240/479/480 边界测试点〔DEC-0302〕；#1/#2 特殊逻辑隔离。
7. 创世工件按 §7 双形式硬编码；`Genesis-ID`/创世时间戳在 C-9 裁决前以占位标注，与第 05 章保持一致。
