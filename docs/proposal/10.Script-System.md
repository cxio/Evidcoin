## 规格正文

### 1. 运行模型〔conception 基本概念 + 0.基本约束〕

脚本是一个**准图灵完备的栈脚本**语言：所有操作基于已定义指令，无自定义函数。运行时存在以下区域：

- **数据栈（Data Stack）：** LIFO，`[]any` 结构；指令实参的兜底来源，返回值默认目标。进入数据栈的具体类型自动转为 `any`。
- **实参区（Arg Area）：** FIFO 队列〔DEC-0501〕；指令需要实参时**优先**从实参区取值，无值再从数据栈取。可持续添加，但取出为**一次性**（整队消费）。解耦指令顺序。
- **附参（Attr Params）：** 编译时固化的硬参数，紧跟 opcode，表达指令属性（如 `IF` 块长、`GOTO` 目标）。静态化优势用于安全敏感参数（如跳转目标）。
- **关联数据（Associated Data）：** 指令直接拥有/控制的数据块（如 `DATA{}` 的字节、`IF{}` 的子语句块）。
- **局部域（Local Scope）：** 块级私有储值空间，仅当前语法块可访问，无上下级继承。
- **全局域（Global Scope）：** 全脚本共享储值空间，任意位置可访问。
- **自动展开（Auto-Spread）：** 多返回值指令将返回值自动展开到目标位置（数据栈/实参区/局部域）。

### 2. 指令的参数配置〔conception 指令的参数配置〕

每个指令配置其实参取值数量：

| 配置值 | 语义 |
|--------|------|
| `0` | 无需实参，不读取实参区。 |
| `n`（>0） | 固定数量；先取实参区，无值再取数据栈；实参区条目数必须匹配（一次性取出）。 |
| `-1` | 不定数量；实参区有值则取出，否则取空值；不访问数据栈。 |
| `-2` | 半确定性；专用于 `CALL`，`实参数量 = 2 + 指令附参值`，运行时确定、静态不确定。 |

### 3. 字节码编码〔DEC-0501〕

- 每条指令以 `opcode`（1 字节）开始。指令码用 1 字节表达，基础指令集 ≤ 255 个（含扩展指令本身，逻辑上可无限扩展）。
- 固定宽度附参按第 01 章大端序编码；变长附参按第 01 章规范 varint（ULEB128 最短）编码。
- 多个附参按文档声明顺序**连续**编码，**不插分隔符**。
- 关联数据按指令自身附参长度读取，**不额外加长度前缀**。
- 解析器必须拒绝：尾随未被任何指令消费的残余字节、截断附参、超长关联数据。

**参数消费顺序〔DEC-0501〕：**

- 实参区 FIFO 取出；数据栈 LIFO 弹出。
- 多个实参按文档参数列表**从左到右**绑定。
- 若从数据栈取多个实参，**最后压栈的值绑定到最右侧参数**。
- 多返回值按文档返回列表从左到右压入目标区域。

**源码与字面量〔DEC-0501〕：**

- 源码仅为显示和编译入口，**不参与链上共识**；链上脚本是编译后的指令值序列。
- 单引号字面量按 Unicode 码点解析：码点 `<= 0xff` 强制编译为 `Byte`，`> 0xff` 编译为 `Rune`。需以 `Rune` 存储 ASCII 字符时，必须用明确的 Rune 构造/转型，不能依赖单引号字面量。
- `BigInt` 正负数字节编码引用第 01 章 `BigIntBytes = slen || magnitude`。
- 文本别名必须编译为唯一 opcode 和附参，不保留名称。

> **后果：** 脚本 hash、交易 hash、脚本成本均基于**字节码**而非源码〔DEC-0501〕。

### 4. 指令分段与命名〔conception 指令码 + 指令命名〕

指令集分四段，合计 **254** 个（可用码位 0~253；255 为基础指令集理论上限）：

| 段 | 码位 | 数量 | 说明 |
|----|------|------|------|
| 基础指令段 | `[0-169]` | 170 | 流程控制、数学运算、栈操作、模式匹配等 |
| 函数指令段 | `[170-224]` | 55 | 高频常用基础功能函数 + 1 个自扩展指令 |
| 模块指令段 | `[225-250]` | 26 | 基本/标准模块 + 1 个自扩展指令 |
| 扩展指令段 | `[251-253]` | 3 | 模块扩展 + 私有扩展（共 3 个，含 1 模块扩展 + 1 私有扩展） |

5 个命名前缀（按特性大类）：

| 前缀 | 大类 | 示例 |
|------|------|------|
| （无前缀） | 基础功能 | `PASS`、`IF`、`TRUE` |
| `SYS_` | 系统调用 | `SYS_TIME{}`、`SYS_AWARD` |
| `FN_` | 功能函数 | `FN_CHECKSIG`、`FN_PUBHASH` |
| `MO_` | 模块引用 | `MO_MATH`、`MO_FMT` |
| `EXT_` | 扩展定制 | `EXT_MO`、`EXT_PRIV` |

**18 类别（按属性划分）：** 1 值指令、2 截取指令、3 栈操作指令、4 集合指令、5 交互指令、6 结果指令、7 流程控制、8 转换指令、9 运算指令、10 比较指令、11 逻辑指令、12 模式指令、13 环境指令、14 工具指令、15 系统指令、16 函数指令、17 模块指令、18 扩展指令。逐类规格见 `Instruction/` 子目录。

> **段 vs 类别的区别：** 段是**码位分配**（4 段，opcode 区间），类别是**功能属性**（18 类）。二者非一一对应：基础段 `[0-169]` 内含 1~14 类，函数段对应第 16 类，模块段对应第 17 类，扩展段对应第 18 类，系统指令（第 15 类）分布于基础段内。

### 5. 三个特例指令〔conception 3个特例指令〕

- **`SYS_NULL`（opcode 169）：** 可在解锁脚本中使用，突破解锁段 opcode `[0-50]` 限制规则〔conception 行 312 明确 opcode = 169〕。
- **`SYS_TIME`：** 因节点当前时间不确定，特别排除，**不可用于公共验证共识逻辑**；公共验证路径触达产生 `ScriptError`〔DEC-0503/0505〕。
- **`CALL`：** `实参数量 = 2 + 指令附参值`（`-2` 半确定性），运行时可定、静态不定，违背静态配置规则。**`CALL` 不属于前期禁用指令**〔DEC-0501/0505〕。

### 6. 缓存区与外部监听〔conception 缓存区和外部监听〕

脚本与外部交互通过**两个完全独立**的缓存区完成（互不互通，服务链外事务）：

- **`INPUT`：** 阻塞式导入。外部注入数据；缓存区无值或数量不匹配则中断退出（不影响调用者 PASS 状态）。**公共验证节点视 `INPUT` 为隐式 `END`/`PassStop`，不导入外部数据**〔DEC-0503/0505〕。
- **`OUTPUT`：** 非阻塞导出，积累到临时导出缓存区。
- **`BUFDUMP`：** 转出导出缓存区数据到外部环境，触发外部监听；监听为私有，仅相关节点部署。

### 7. 注册表与环境边界〔DEC-0503〕

**注册表（子空间分立编号，不共享数值语义）：**

- opcode 是一级注册表，固定 1 字节。
- `ENV`、`IN`、`OUT`、`VALUE`、`FN`、`MO`、`EXT` 等子空间**各自独立**维护编号。
- 当前 `docs/proposal/Instruction/*.md`（追溯自 conception 指令文档）已列出的 opcode、附参子空间、值名称为**冻结基线**。
- 禁用指令仍保留编号；新增注册项只能**追加**，不得复用已发布编号。

**公共验证边界（不得依赖不确定结果）：**

- 公共验证路径不得依赖本地时钟、外部输入、外部程序、私有扩展、网络查询的不确定结果。
- `SYS_TIME` 不得位于公共验证路径；`EXT_PRIV` 在公共验证路径非法（产生 `ScriptError`）。
- `INPUT` 在公共验证节点视为隐式结束。
- `SHELL` 在公共验证路径被忽略（不执行本地程序、不产生公共副作用），但**正常消费实参、执行栈/类型检查、计入公共成本**〔DEC-0503/0505〕。
- `GOTO`、`EMBED` 只能引用已确认且可验证的链上脚本；目标缺失/不可验证时归为 `ScriptError`，交易失败（不得恢复为 `false` 或忽略）。
- 已启用外部引用指令**优先**读取用户提供的验证上下文数据，无果后才触发网络查询。
- 当前主网公共验证实际执行路径触达 `SCRIPT` 或 `INOUT` 时**立即** `ScriptError`，不进入上下文读取或网络查询。

**环境命名〔DEC-0503〕：** 区块推导时间用 `BlockTime`；交易时间戳用 `TxTime`；当前输入、来源输出、当前输出等环境必须显式区分。

> **外部引用的验证上下文携带〔conception AGENTS〕：** `SCRIPT`/`GOTO`/`EMBED`/`INOUT` 需引用历史交易。设计允许交易携带相关历史信息与验证上下文（输出项的默克尔验证路径），免去验证节点网络查询。常用外部引用（如通用介管脚本）由节点缓存，用户可省略额外历史数据，只广播纯交易。

### 8. 浮点 profile〔DEC-0502〕

- `Float` = IEEE 754 binary64；字节编码 8 字节大端 bit pattern。
- 输入字面量不得表达 NaN/+Inf/-Inf；`POW`/除零/溢出等产生 NaN/Inf 时不崩溃，保留异常值继续执行，由 `ISEFV` 检测。
- `-0.0` 数值比较等于 `+0.0`，但字节编码保持原 bit pattern。
- `Float -> Int` 默认向零截断；`Float -> String` 默认最短 round-trip 十进制（等价 Go `strconv.FormatFloat(f,'g',-1,64)`），可由 `STRING{e/E/f/g/G/x/X}` 指定格式。
- `BYTES`/`PACK` 对 `Float` 输出 IEEE 754 binary64 8 字节大端；异常浮点也可被输出为 bit pattern，转换后类型为 `Bytes`，不再触发最终异常 `Float` 残留检查。
- **比较规则：** 任一操作数为 NaN 时（除 `ISEFV`）比较返回 `false`；`EQUAL(+0.0, -0.0)` 为 `true`；排序类比较遇 NaN 导致脚本执行失败、验证不通过。

> 高精度金额逻辑应使用 `Int`/`BigInt`，不要用 `Float`〔DEC-0502〕。

### 9. 执行状态机〔DEC-0505〕

**执行状态：**

| 状态 | 语义 | 共识后果 |
|------|------|----------|
| `Running` | 继续执行 | — |
| `PassStop` | 正常结束，返回当前 PASS 状态 | `PassStop(true)` 通过；`PassStop(false)` 交易不合法 |
| `VerifyFail` | 验证失败 | 交易不合法 |
| `ScriptError` | 脚本错误（类型错误/栈下溢/非法 opcode/禁用指令触达等） | 交易不合法 |
| `CostFail` | 成本超限 | 交易不合法 |
| `PrivateStop` | 私有路径停止 | 不影响公共验证结果 |

**通关状态语义：**

- 初始通关状态为 `true`。
- `PASS` 与 `CHECK` 均写入当前通关状态，**后写入者覆盖前值**。
- `PASS false` 写入 `false` 后立即 `VerifyFail`；`PASS true` 继续执行；`CHECK true/false` 写入后继续执行。
- `END` 和公共验证路径中的 `INPUT` 以当前通关状态产生 `PassStop`。
- `PassStop(false)` 不等同于 `PASS false` 的立即失败，但最终共识后果同为交易不合法。

**停止与私有路径：**

- 公共验证在 `END` 或公共 `INPUT` 后停止；停止后私有路径产生的 `OUTPUT`/`BUFDUMP`/`PRINT` 等私有副作用不记录、不比较、不参与共识。
- 公共 `END`/`INPUT` 之后的私有路径仍必须是可解析字节码，但公共验证不执行、不计成本，也不因其中的禁用指令拒绝〔DEC-0501/0504/0505〕。

### 10. 成本模型框架〔DEC-0504〕

- 每条指令有 `base_cost`；按输入字节数、输出字节数、哈希次数、签名验证次数、正则复杂度、脚本引用次数增加动态成本。
- 内存成本按峰值数据栈字节数、实参区字节数、局部域字节数计入。
- 成本函数**只依赖**脚本字节码、共识环境、验证材料、运行时确定数据，**不依赖**硬件性能、缓存命中、网络查询耗时、节点本地状态。**返回确定性值**〔conception 执行成本 + DEC-0504〕。
- 成本按**实际执行路径**累计；未执行分支不计运行成本。`EACH`/`MAP`/`FILTER` 按实际迭代次数与处理数据量计入。
- 成本超限产生 `CostFail`，交易不合法。

**三层上限：**

| 上限 | 范围 |
|------|------|
| `MaxInputScriptCost` | 单输入 |
| `MaxTxScriptCost` | 单交易所有脚本 |
| `MaxBlockScriptCost` | 单区块所有脚本（**固定协议上限，不随区块容量年度增长**） |

**外部引用计数〔DEC-0504〕：** `GOTO`/`EMBED` 在目标解析成功前**先计数**；其引用基础成本、验证上下文处理成本、目标脚本执行成本均归属**调用方**（计入当前输入/交易/区块预算）；目标缺失/不可验证/解析失败时已产生的计数与成本仍保留，然后交易验证失败。

> **暂不设计**按成本提高交易费的协议功能（初期简化）〔conception 执行成本 + DEC-0504〕。

### 11. 解锁数据与解锁段限制〔conception 解锁数据 + 参数限定〕

解锁数据 = **见证信息**（标准验证所需）+ **解锁脚本**（合约需求/定制验证）。

- 解锁脚本可用指令严格限制在 opcode `[0-50]`：即值指令、截取指令、栈操作指令、集合指令、交互指令等。理由：保证安全性与可审计性，避免复杂逻辑（"一个 `TRUE PASS EXIT` 序列能做任何事"）。
- **特例：** `SYS_NULL`（opcode 169）作为例外可在解锁脚本使用，突破 `[0-50]` 限制。
- 在解锁脚本中导入外部脚本（`SCRIPT`）可能导致交易校验优先级降低（且 `SCRIPT` 当前为禁用指令，见第 12 节）。

### 12. 禁用指令与公共路径边界〔conception AGENTS + DEC-0505〕

**前期禁用指令清单（当前主网，4 项）：**

| 指令 | 禁用理由 |
|------|----------|
| `SCRIPT` | 额外验证成本，前期不常用 |
| `VALUE` | 获取某值指令，前期无明确使用场景 |
| `EVAL` | 运行时新脚本执行，前期场景不明 |
| `INOUT` | 获取输入项源输出集数据，额外验证成本且场景不明 |

**执行边界：**

- 禁用不是"未实现则忽略"；当前协议有效交易不得依赖禁用指令。这些指令仍需实现，运行于 `testnet`/`devnet`〔conception AGENTS〕。
- 禁用指令仍保留 opcode 定义；只在**公共验证实际执行路径触达时**产生 `ScriptError`，不是仅因脚本静态出现即拒绝〔DEC-0501/0505〕。
- 公共 `END`/`INPUT` 停止后的私有路径可保留禁用指令，但不得影响公共验证结果。
- 私有工具可解析/显示禁用指令，但必须标注当前禁用状态。
- `CALL`、`SHELL` **不属于**禁用指令〔DEC-0505〕。

### 13. 参数限定（硬资源上限）〔conception 参数限定〕

| 限制 | 取值 | 备注 |
|------|------|------|
| 数据栈高度 | `< 256` | 即 `MaxStackHeight = 255` |
| 栈数据项大小 | `< 4KB` | 即 `MaxStackItem = 4095` |
| 锁定/识别脚本长度 | `< 8KB` | 即 `MaxLockScript = 8191` |
| 解锁脚本长度 | `< 8KB` | `MaxUnlockScript = 8191`；不含标准内置验证见证信息；定制验证若把签名放入解锁脚本则计入 |
| 描述/内容长度 | `< 2KB` | 凭信描述/存证内容，避免恶意填充影响 `GOTO/EMBED` 验证 |
| `EMBED` 嵌入次数 | `<= 4` | 运行时计数 |
| `EMBED` 嵌入深度 | `== 0` | 嵌入脚本不可再有 `EMBED`/`GOTO` |
| `GOTO` 跳转次数 | `<= 2` | 顶层主脚本，运行时计数 |
| `GOTO` 跳转深度 | `<= 3` | 运行时计数（参考：管理者+审计者+第三方） |

> 锁定脚本长度检查含两项：①作为输入项的引用源输出锁定脚本（已既成事实）；②当前交易每个输出项锁定脚本（超限则交易被拒）〔conception 参数限定〕。常量数值详见第 03 章。

## 边界与限制

- 本章承载脚本系统**框架与规则**；**指令逐条规格**（opcode、附参、实参、返回、说明）由 `Instruction/` 子目录承载，本章为其总则。
- 成本模型只冻结**框架**：具体 opcode `base_cost`、动态成本公式、三层上限数值未冻结（见待决 C-6）。
- 禁用解除方式（逐项 opcode 激活 vs 统一版本激活）未由 conception 固定（见待决 C-7）；解除须由 conception 或新 DEC 指定协议版本/激活高度。
- P2P/外部数据网络（Depots）线格式不在本章范围；外部引用的网络查询接口边界见第 15 章。

## 对 Plan 的约束

1. `internal/script` 必须实现字节码解析器，严格执行 DEC-0501 编码规则（拒绝残余字节/截断附参/超长关联数据），参数消费顺序按 FIFO 实参区 + LIFO 数据栈 + 左到右绑定。
2. 必须实现执行状态机（`Running`/`PassStop`/`VerifyFail`/`ScriptError`/`CostFail`/`PrivateStop`）与通关状态语义（后写入覆盖、`PASS false` 立即失败）。
3. 必须区分公共验证路径与私有路径：公共路径禁用 `SYS_TIME`/`EXT_PRIV`/`SCRIPT`/`INOUT`，忽略 `SHELL`（消费实参），`INPUT` 视为隐式停止；私有路径不参与共识。
4. 必须实现解锁段 opcode `[0-50]` 限制及 `SYS_NULL`（169）特例；超限指令在解锁脚本中非法。
5. 浮点严格按 DEC-0502 binary64 profile（异常浮点、比较、转换、字节编码）实现，禁用受 fast-math 影响的非标准行为。
6. 成本模型按 DEC-0504 框架实现（确定性、实际执行路径计费、外部引用计数归调用方）；具体数值在 C-6 裁决前以占位/可配置常量实现，不进入主网共识。
7. 禁用指令（SCRIPT/VALUE/EVAL/INOUT）须实现于 testnet/devnet，主网公共路径触达即 `ScriptError`；C-7 裁决前不实现解除激活逻辑。
8. 指令逐条实现追溯到 `Instruction/` 子目录与对应 DEC，注册表子空间编号不得复用。
