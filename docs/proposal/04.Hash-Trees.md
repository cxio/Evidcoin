- **职责：** 定义全协议通用二叉哈希树构造、验证路径编码，以及各专用树的叶子/根规则。

## 规格正文

### 1. 通用二叉哈希树〔DEC-0004〕

适用范围：区块交易树、交易输入/输出哈希树、UTXO/UTCO 中间层等链上共识用途。
**例外：** 附件片组哈希树按 DEC-0002 例外（不带域标签，见 §3.2）。

- **分支节点前像：** `DomainTag("tree.branch") || leftHash || rightHash`，算法 BLAKE3-256（见第 02 章）。
- **叶子节点前像：** `DomainTag("tree.leaf") || payload`；`payload` 由各具体结构定义内部排布（序号若存在，作为 payload 内部前缀）。默认算法 SHA3-384。
- **奇数层提升：** 奇数层最后一个节点**直接提升**到下一层，**不复制自身**。
- **单叶树根：** 单叶树根等于该叶哈希，**不**额外套一层分支哈希。
- **空根：** 由各结构自定义；UTXO/UTCO 空根见第 09 章（DEC-0201），域标签 `utxo.empty`/`utco.empty`（见第 02 章全集）。

### 2. 通用验证路径编码〔DEC-0004〕

```text
Proof = {
    leafHash,        // 已含序号等 payload
    siblings[]: { direction (0=左 / 1=右), hash },
    rootHash
}
```

- 验证路径**不单独携带 `leafIndex` 字段**；若需按序号定位，序号已包含在 payload 中，由 leaf 哈希反演即可。
- 必须携带 `direction` 方向信息。

### 3. 专用树

#### 3.1 区块交易树〔blockchain.md + DEC-0004〕

- 叶子 payload = `seq(3 bytes, 大端) || TxID`。
- 叶子哈希 = `SHA3-384( DomainTag("tree.leaf") || seq || TxID )`。
- 3 字节序号是叶子哈希前像的一部分，**不**作为通用 `leafIndex` 字段。
- 即使区块仅含一笔交易（如创世块），叶子仍前置 3 字节序号（`000`）计算（见第 05 章）。

#### 3.2 附件片组哈希树〔DEC-0002 例外 + DEC-0004〕

- 叶子哈希 = `BLAKE3-256( 2-byte seq || BLAKE3-256(piece_data) )`，**不带域标签**。
- 分支哈希 = `BLAKE3-256( left || right )`，**不带域标签**。
- 序号同样是叶子前像内部前缀。
- 这是全局"前像首段必须为域标签"规则的**唯一例外**（与第 02 章 §4 一致），面向通用文件分享（Depots，见第 15 章）。
- 与区块交易树虽都用序号前缀，但域标签差异 + 算法不同（SHA3-384 vs BLAKE3-256）→ 不同名字空间，无混淆风险。

#### 3.3 交易输入根〔附.交易.md + DEC-0004〕

- 交易输入集为 **2 层**树（叶子 + 根），因对输入项无后期检索需求。
- 输入根 = `BLAKE3-256( ListHash || LeadPKHash )`（`Hash256` = BLAKE3-256，见第 02 章）。
  - `ListHash = Hash384( ListOf(Inputs) )` —— 输入项串联哈希。
  - `LeadPKHash` —— 首领输入源公钥哈希，参与计算以便铸造者验证。
- **不**套通用二叉树构造。
- 字段细节（编码、Coinbase 省略 `HashInputs`）见第 06 章。

#### 3.4 交易输出树〔blockchain.md + DEC-0004〕

- 输出树根 = `Hash256( Tree<Outputs> )`，即对输出集套用通用二叉树（§1），根再取 BLAKE3-256。
- conception 记为 `HashOutputs = BLAKE3-256( SHA3-384(LeafData) )` 的常规计算（叶 SHA3-384、根/枝 BLAKE3-256）。
- 字段细节见第 06 章。

#### 3.5 UTXO/UTCO 宽成员状态树（引向第 09 章）

- UTXO/UTCO 指纹为**宽成员**状态树，分层结构由 DEC-0201 定义（4 层，年度+TxID 分层 `[8,13,18]`），**不**直接套通用二叉证明格式。
- 其分支节点仍按 `tree.branch` 域标签编码；末端叶 SHA3-384（`utxo.leaf`/`utco.leaf`）。
- 空根 `utxo.empty`/`utco.empty` 与第 02 章域标签全集一致。
- 完整分层、叶子前像、空根计算由**第 09 章承载**。

## 边界与限制

- 奇数叶不复制；单叶即根——禁止人为重复数据。
- 通用验证路径禁止携带 `leafIndex`。
- 附件片组树是唯一免域标签的树；其它链上树必须前置域标签。

## 对 Plan 的约束

1. `pkg/hashtree` 实现一套通用二叉树构造与证明验证（含奇数层提升、单叶即根、方向位），供区块交易树/输入树/输出树/UTXO·UTCO 中间层复用；`pkg/types` 仅承载基础 Hash/ID/编码类型。
2. 区块交易树叶子必须含 3 字节大端序号前缀，进入叶哈希。
3. 附件片组树必须走免域标签路径，与链上树共用算法但隔离名字空间。
4. 交易输入根、UTXO/UTCO 指纹分别遵循第 06、09 章的专用规则，不套通用二叉证明格式。
