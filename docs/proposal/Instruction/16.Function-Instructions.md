# Function Instructions（函数指令）

## 来源构想

- `docs/conception/Instruction/16.函数指令.md`：定义 opcode `170-224`。
- `docs/proposal/02.Cryptography-And-Hashing.md`：定义 Hash、地址和签名算法边界。
- `docs/proposal/03.Identifiers-And-Constants.md`：定义 ADR-0020 地址文本编码。
- `docs/proposal/Instruction/0.Base-Constraints.md`：定义函数调用和成本边界。

## 范围

函数指令包括高频标准函数和自扩展函数：

- Base58/Base32/Base64 编码解码。
- Address 编码/解码。
- PubHash / MPubHash。
- CheckSig / MCheckSig。
- Hash224 / Hash256 / Hash384 / Hash512。
- Printf。
- `FN_X` 标准函数扩展引用。

## 规范要求

- Base 编码必须固定具体字母表、padding、大小写和错误规则。
- Address 函数必须使用 ADR-0020 固定的地址文本编码：`"Cx" + Base58Check(AddressHash)`，checksum 为 `SHA3-256(SHA3-256(AddressHash))[0:4]`。
- PubHash 必须使用规范化公钥材料。
- MPubHash 必须固定 `M-Of-N`、排序和重复处理。
- CheckSig/MCheckSig 必须使用交易 Proposal 定义的签名消息。
- CheckSig/MCheckSig 的签名字节来自普通脚本实参，可由 UnlockScript 入栈或进入实参区；它们不读取 Witness，也不要求 Witness 存在。
- Hash 函数输出长度必须与 `02.Cryptography-And-Hashing.md` 对齐。
- `FN_X` 必须有注册表、版本和成本规则，不能自由扩散。

## 风险

- Address 编解码必须拒绝错误前缀、非法 Base58 字符、长度错误和 checksum 不匹配。
- Base58/Base32/Base64 变体差异很大。
- 签名函数若绕过交易签名消息，会造成重放风险。
- `FN_X` 无治理会造成实现碎片化。

## 未决问题

- 多签复合地址的 `M-Of-N`、排序和重复规则；地址文本前缀、checksum 和 Base58Check 已由 ADR-0020 关闭。
- Hash224 是否存在协议级用途。
- 多签排序和重复规则。
- `FN_X` 注册表治理。
- Printf 是否允许公共验证执行。

## 对后续 Plan 的影响

- 函数测试必须使用固定算法测试向量，并覆盖 ADR-0020 地址编码成功、前缀错误和 checksum 失败。
- 签名函数必须复用 `pkg/crypto` 抽象。
