# 函数指令（Function Instructions）

## 来源追溯

- `docs/conception/Instruction/16.函数指令.md` —— opcode `[170-224]` 逐条定义、基础函数集 + 标准函数集。
- `docs/conception/附.交易.md` —— 多重签名验证逻辑。
- `docs/conception/blockchain.md` / 第 02 章 —— 哈希算法分配与公钥哈希构造。
- `DEC-0501` —— `FN_X` 标准函数引用作为函数段、半确定性调用目标可验证。
- `DEC-0504` —— 函数指令成本归类。

## 概述

- **opcode 区间：** `[170-224]`，55 个（基础函数集 + 标准函数集，含未用 182-222）。前缀 `FN_`。
- **职责：** 语言基本语法之外、形如函数的指令；多数无附参，由动态实参输入。
- **段位置：** 对应**函数段**（第 10 章码位分配，与基础段区分）。
- **前置：** `0.Base-Constraints.md`。

## 规格正文

### 基础函数集

| opcode | 函数 | 实参 → 返回 | 规格 |
|--------|------|-------------|------|
| 170 | `FN_BASE58` | Bytes/String → String/Bytes | Base58 编解码（视实参类型）。 |
| 171 | `FN_BASE32` | Bytes/String → String/Bytes | Base32 编解码；RFC4648 大写 + 234567，无填充。 |
| 172 | `FN_BASE64` | Bytes/String → String/Bytes | Base64 编解码；无填充，URL 友好字符(`-_`)。 |
| 173 | `FN_ADDRESS` | (data, prefix) → String/Bytes | 公钥哈希↔账户地址(Base58)。编码：加前缀→2 次哈希取末 4 字节校验码→`[哈希\|\|校验码]`→编码加前缀。解码：分离前缀→解码切分→重算校验码比对。文本地址仅 UI 展示与输入合法性验证。 |
| 174 | `FN_PUBHASH` | Bytes → Bytes | 从公钥创建单签公钥哈希（编码/哈希操作）。 |
| 175 | `FN_MPUBHASH` | ([]baseHash, m, n byte) → Bytes | 创建多签复合公钥哈希。各公钥初级哈希(BLAKE3-256)有序串连 + 前置 `m/N`(2 字节)→哈希。`m<=N`。 |
| 176 | `FN_CHECKSIG` | (chk_type, auth_flag byte, sig, pubKey Bytes) → Bool | 单签验证。chk_type：1=币金,2=凭信；auth_flag 约束签名消息；sig/pubKey 可由解锁脚本作普通数据提供。验证成功系统层标注。chk_type 高位预留未来用途。 |
| 177 | `FN_MCHECKSIG` | (chk_type, auth_flag byte, []sigs, []pubKeys, []baseHashs) → Bool | 多签验证。签名集与公钥集一一对应；baseHashs=剩余公钥初级哈希集；不依赖见证信息。成功系统层标注。 |
| 178 | `FN_HASH224(1)` | Bytes → Bytes(28B) | 224 位哈希；附参算法：0=BLAKE3(默认),1=BLAKE2(blake2b),2=SHA2,3=SHA3；`{name}` 小写。 |
| 179 | `FN_HASH256(1)` | Bytes → Bytes(32B) | 256 位哈希；算法标识同上。例：`FN_HASH256{blake3}`/`[0]`/默认。 |
| 180 | `FN_HASH384(1)` | Bytes → Bytes(48B) | 384 位哈希；算法标识同上。 |
| 181 | `FN_HASH512(1)` | Bytes → Bytes(64B) | 512 位哈希；算法标识同上。 |
| 182-222 | （未用） | — | 保留，不分配（41 个）。 |
| 223 | `FN_PRINTF` | (fmt string, val ...any) → nil | 控制台打印（`fmt.Printf`）；与标准打印指令 `PRINT` 不同。 |

### 标准函数集

| opcode | 指令 | 附参/实参 | 规格 |
|--------|------|-----------|------|
| 224 | `FN_X(1){}` | 附参=目标索引(花括号可写目标名别名)；实参视目标而定 | 标准函数引用：调用目标位置的标准函数。标准函数集仅 1 字节空间（最多 256 个），与普通函数指令一样需配置参数数量直接调用；**通常仅由官方定义发布**。公共验证须能静态定位目标函数与成本〔DEC-0501〕。 |

## 边界与限制

- 哈希算法标识 0-3（BLAKE3/BLAKE2/SHA2/SHA3）；输出长度由 opcode 决定（224/256/384/512）。
- `FN_CHECKSIG`/`FN_MCHECKSIG` 验证成功在系统层标注供 `SIGNED`/`SYS_CHKPASS` 引用。
- `FN_X` 标准函数集上限 256，官方发布；目标索引须静态可定位。

## 待决问题

- 标准函数集（`FN_X` 目标）具体清单由官方后续定义。
- 未用区 182-222 留待扩展。

## 对 Plan 的约束

1. 实现编码函数（Base58/32/64、Address）与哈希函数（多算法、多长度）；哈希算法引用第 02 章分配。
2. `FN_PUBHASH`/`FN_MPUBHASH` 按公钥哈希构造规则（第 02 章）；`FN_CHECKSIG`/`FN_MCHECKSIG` 按附.交易签名逻辑、系统层标注。
3. `FN_X` 标准函数注册表（≤256），目标索引静态可定位、成本可分析（DEC-0501）。
