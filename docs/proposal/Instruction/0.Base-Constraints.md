## 规格正文

### 1. 指令结构〔0.基本约束 + DEC-0501〕

每条指令由以下部分构成（除 opcode 外均按指令而定可选）：

- **opcode：** 1 字节，必需，唯一标识指令。
- **附参（attached params）：** 编译期固化，表达指令属性；固定宽度按大端、变长按 ULEB128 编码；多附参按声明顺序连续编码，无分隔符〔DEC-0501〕。
- **关联数据（associated data）：** 指令直接携带的数据块；按指令自身附参长度读取，无额外长度前缀〔DEC-0501〕。
- **运行时实参（runtime args）：** 不属于指令字节码本身，运行时从实参区/数据栈取得。

链上脚本是已编译字节码；源码文本、注释、友好缩写、示例语法**不参与** Hash 或签名输入〔DEC-0501〕。

### 2. 运行时空间〔0.基本约束 + 6.脚本系统〕

- **数据栈：** LIFO，`[]any`，存放运行时值与返回值。
- **实参区：** FIFO，临时存放指令实参；一次性整队消费。
- **局部域：** 块级私有，静态堆叠空间（容量 128），无父子继承，仅同级共享〔2.截取指令〕。
- **全局域：** 脚本域共享；`GOTO` 不继承，`EMBED` 共享〔13.环境指令〕。
- **INPUT/OUTPUT 缓存区：** 两个独立 FIFO 通道，不互通。

### 3. 实参模型〔conception 指令的参数配置〕

| 模型 | 语义 |
|------|------|
| `0` | 无实参，不读实参区 |
| `n`（>0） | 固定数量；实参区为空则取数据栈 `n` 个；实参区非空则数量必须恰为 `n`（不足/过多均失败，不部分消费） |
| `-1` | 不定数量；只读实参区，空则空实参，不访问数据栈 |
| `-2` | 半确定性；仅 `CALL`，数量 = `2 + 附参值`，运行时确定 |

**参数绑定〔DEC-0501〕：** 多实参按文档列表从左到右绑定；从数据栈取多实参时，最后压栈值绑定最右参数；多返回值从左到右压入目标区域。

### 4. 截取与自动展开〔2.截取指令 + 自动展开〕

- 截取指令（`@`/`$`）改变目标指令返回值的去向（实参区/局部域）。
- 自动展开只适用于明确声明返回多值的指令；返回单个 Slice 的指令默认不展开（除非显式 `SPREAD` 或专门声明）。
- `~`（实参直取）只影响目标指令取参来源（强制走数据栈），不改返回值去向；与 `@`/`$` 同用时应位于其后、目标指令之前。

### 5. 执行状态与脚本行为〔0.基本约束 + DEC-0505〕

- **结束：** 执行到脚本末尾或 `END`/`EXIT`，以通关状态决定验证结果。
- **失败：** 错误使 PASS 无效，验证不通过。
- **中断退出：** 与正常结束类似但有别（主要 `INPUT` 无数据时），不影响 PASS 状态。
- 完整状态机（`Running`/`PassStop`/`VerifyFail`/`ScriptError`/`CostFail`/`PrivateStop`）与通关语义见第 10 章第 9 节及 `6.Result-Instructions.md`。
- 初始通关状态为 `true`；`PASS`/`CHECK` 后写入覆盖前值；`PASS false` 立即失败〔DEC-0505〕。

### 6. 公共验证边界〔DEC-0503/0505〕

公共验证路径不得依赖：本机真实时间、系统随机源、Shell、私有扩展、未验证外部输入、服务节点未验证数据。

- 禁用指令只在公共验证**实际执行路径触达**时拒绝（`ScriptError`），不是仅因静态出现即拒绝〔DEC-0501/0505〕。
- 私有逻辑应位于 `END`、公共 `INPUT` 或等价公共结束边界之后；公共节点忽略私有逻辑。

### 7. 字节码解析约束〔DEC-0501〕

- 解析器必须拒绝：尾随未消费残余字节、截断附参、超长关联数据。
- 文本别名编译为唯一 opcode 与附参，不保留名称。
- 单引号字面量按 Unicode 码点解析：`<=0xff` 编译为 `Byte`，`>0xff` 编译为 `Rune`〔见 `1.Value-Instructions.md`〕。

## 边界与限制

- 本文件只承载**元规则**；逐条指令规格在各类文件。
- 成本模型框架见第 10 章第 10 节；具体数值未冻结（C-6）。
- 禁用指令清单见第 12 节风格说明与 `15`/`14`/`1` 类文件标注。

## 对 Plan 的约束

1. 所有指令实现必须先通过**统一字节码解析器**（DEC-0501 规则）。
2. 执行器必须有统一的错误/失败/结束/通关状态模型（DEC-0505）。
3. 每条指令在实现侧维护元数据：opcode、mnemonic、附参 schema、关联数据 schema、实参数量模型、返回数量、解锁段可用性、确定性标记、公共/私有可用性、成本类别、错误情形。
4. 每类指令测试覆盖取参来源、返回值去向、资源限制、公共/私有边界。
