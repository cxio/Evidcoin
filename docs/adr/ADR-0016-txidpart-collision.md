# ADR-0016: 输入项 TxIDPart 碰撞处理

## Status（状态）

Accepted

## Context（背景）

普通交易的 RestInput（非首领输入）使用 TxID 前 20 字节（`TxIDPart`）加 Year 和 OutIndex 定位来源输出。20 字节 = 160 位的局部引用存在哈希碰撞理论风险（生日攻击阈值约 2^80）。

提案层已规定：当 20 字节局部引用产生歧义时（即同一年度内存在两个前 20 字节相同的 TxID），该交易**必须拒绝**。评审报告（M-4）建议分析碰撞概率和长期性能影响。

## Decision（决策）

**维持现有设计，简化处理，不增加额外复杂性。**

具体策略：
- 碰撞歧义时拒绝交易（维持现有规则）。
- 不扩展 TxIDPart 的字节长度。
- 不预留升级路径（不预设 Version 字段用于此目的）。

## Rationale（理由）

1. **年度分区大幅降低碰撞空间**：TxID 引用系统的顶层有年度（Year）分区，碰撞只需要在同一年度内发生。Evidcoin 的区块间隔为 6 分钟，每年约 87661 个区块，每块最多约 64k 笔交易，单年度理论最大交易量约 57 亿笔（实际远低于此）。在 57 亿个随机 160 位 Hash 中，两个前 20 字节相同的碰撞概率仍约为 `(57亿)^2 / 2^160 ≈ 5.7 × 10^-31`，即每年发生一次碰撞的概率约为 `10^-30` 量级，几乎不可能发生。
2. **遇碰撞不影响安全性**：即使极小概率的碰撞发生，交易仅被拒绝（用户体验轻微下降），不会造成资产损失或安全漏洞，因为拒绝是保守安全策略。
3. **无需增加复杂性**：为一个概率约为 `10^-30` 的事件增加额外的协议层复杂度（如版本字段、动态扩展机制），违反 YAGNI 原则，得不偿失。

## Consequences（影响）

- 无需修改现有提案或计划文档（拒绝策略已存在）。
- `internal/utxo`/`internal/utco` 的局部引用解析函数在检测到歧义时返回明确的 `ErrTxIDPartAmbiguous` 错误。
- 需在文档中补充碰撞概率的估算数据，作为此设计决策的背书。
