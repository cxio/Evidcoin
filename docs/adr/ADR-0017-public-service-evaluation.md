# ADR-0017: 公共服务质量评估策略

## Status（状态）

Accepted

## Context（背景）

Evidcoin 的激励机制（`docs/proposal/14.Incentives-And-Coinbase-Rewards.md`）通过 Coinbase 奖励分配，将区块收益的一部分（Depots 20%、Blockqs 20%、stun2p 10%）分配给公共服务节点。

铸造者需要在 Coinbase 中填写公共服务节点的收益地址，其对服务质量的确认是"主观但受利益约束"的行为。评审报告（M-5）指出可能存在铸造者与自营服务节点形成自我奖励闭环的风险，并建议引入客观可验证的服务质量度量。

## Decision（决策）

**在项目初期阶段，不引入客观的服务质量验证机制。维持现有基于铸造者主观确认的激励模式。**

理由：
- Blockqs 的查询可用性证明如何设计？需要哪种类型的证明？能有效抑制作弊吗？
- Depots 的数据存储证明虽然可以通过分片哈希的序数抽查，但依然能发展出专门的作弊手段。
- 复杂的链上服务质量验证机制设计、实现和维护成本高，且可能在初期引入新的攻击面。

初期阶段的作弊风险由市场竞争和社区声誉机制约束：铸造者自己选择服务质量差的节点，只会损害自身体验和网络竞争力。

## Rationale（理由）

本 ADR 认可这是一个有意的设计妥协。核心判断是：

1. **机制设计难度高**：链上服务质量证明（PoUW/PoS/抽查等）是区块链领域尚未完全解决的开放问题，现有方案均存在作弊手段。
2. **初期规模有限**：在网络早期，节点数量少，社区监督成本低，自我奖励闭环更容易被发现和施压。
3. **价值与复杂性权衡**：项目初期的主要目标是验证核心共识机制（PoH）和三种信元模型的可行性，引入未成熟的服务质量验证会转移注意力。

此决策在未来条件成熟时可以通过协议升级（硬升级）引入更严格的验证机制。

## Consequences（影响）

- 无需在当前阶段修改激励机制提案。
- 需在 `docs/proposal/14.Incentives-And-Coinbase-Rewards.md` 中补充说明：初期采用主观确认模式，后续版本可能引入客观验证。
- 此问题保持开放，不关闭；后续专项研究时可升格为新的 ADR。
