# ADR-0011: 铸凭哈希碰撞的决胜规则

## Status（状态）

Accepted

## Context（背景）

PoH 共识中，MintHash 值较小的铸造候选者胜出。MintHash 为 64 字节（512 位）的 BLAKE3-512-XOF 输出。

理论上存在两个不同的铸凭交易计算出完全相同 MintHash 的可能。评审报告（H-7）建议为此定义 tie-breaker 规则，以避免不同节点选择不同胜者导致分叉（OQ-019）。

## Decision（决策）

**按“先到先得”执行：节点不接受相同 MintHash 的第二个申请进入择优池。**

- 若两个不同铸凭交易（不同 mintTxID）产生完全相同的 64 字节 MintHash，节点仅保留**先到达**的那个候选，后续相同 MintHash 的候选一律拒绝进入择优池。
- 该策略在极低概率的 2^512 碰撞情况下仍可能导致分叉（不同节点“先到”的候选不同），此分叉交由既成事实原则（社会共识）裁决。

## Rationale（理由）

1. **概率极低，无需复杂规则**：MintHash 为 512 位空间，两个不同铸凭哈希在 512 位空间中发生碰撞的概率约为 `1 / 2^256`（生日攻击下限）。在有效铸凭交易约 80000 个的窗口内，碰撞概率约为 `(80000)^2 / 2^512 ≈ 2^-495`。这是一个"命运"级事件。
2. **先到先得更自然**：择优池本质是一个实时候选集合，天然具备“先到先得”的入池语义。禁止相同 MintHash 的第二个申请进入，与网络实际传播模型一致。
3. **分叉成本可接受**：即便极低概率发生碰撞，不同节点先收到的候选可能不同，从而导致短期分叉。该分叉将在 29 区块内被自然竞争解决（端点约定中的分叉选择机制），不会造成永久分叉。
4. **实现简单且明确**：无需引入额外排序或 tie-breaker 字段，只需在入池时检查“MintHash 是否已存在”。

## 注意：双签场景与本 ADR 的边界

本 ADR 处理的是**不同铸凭交易之间发生的哈希碰撞**（不同 mintTxID → 相同 MintHash），属于择优池内部的候选选择问题。

与此不同的另一个场景是：**同一铸造者对两条竞争分叉分别双签**（相同 mintTxID → 必然相同 MintHash），此时问题升级为分叉竞争平局，由 ADR-0027 定义的分叉决胜规则（BlockID 字典序 + 交易费低者优先）予以处理。

两类 MintHash 相等情形的对比：

| 场景 | mintTxID | 处理层 | 规则 |
|------|----------|--------|------|
| 哈希碰撞 | 两个不同值 | 择优池（单区块候选选择） | 先到先得（本 ADR） |
| 铸造者双签 | 相同值 | 分叉选择（多区块竞争） | BlockID 字典序（ADR-0027） |

## Consequences（影响）

- 需在 `docs/proposal/10.PoH-Consensus.md` 中明确"择优池对相同 MintHash 的入池规则：只保留先到者"。
- `internal/consensus` 的择优池实现需在入池时做"MintHash 已存在则拒绝"的判定；不再允许实现者自行决定同哈希候选的保留策略。
- OQ-019 关闭。
