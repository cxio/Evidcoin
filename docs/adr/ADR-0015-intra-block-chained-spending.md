# ADR-0015: 同区块内链式消费规则

## Status（状态）

Accepted

## Context（背景）

在 Bitcoin 等 UTXO 模型中，一个区块内的交易通常按顺序排列，后续交易可以消费同一区块内前序交易的输出（区块内链式消费）。

Evidcoin 的 `docs/proposal/08.UTXO-UTCO-State.md` 对此问题"倾向于禁止但未最终决定"。此决策影响：
- 交易打包的灵活性（允许时，同一区块可以构造依赖链）
- 校验组的任务分派（禁止时，所有交易可以并行独立验证）
- 安全性（允许时，可构造长依赖链作为攻击手段）

## Decision（决策）

**明确禁止同区块内链式消费**。

即：一个区块中，任何交易的输入只能引用**已被确认的历史区块**中的输出（UTXO/UTCO），不能引用同一区块内的任何其他交易的输出，无论该交易在区块中的排列顺序早于还是晚于当前交易。

## Rationale（理由）

1. **防止长依赖攻击**：若允许区块内链式消费，攻击者可构造深度依赖链（A→B→C→...→Z），校验节点必须按序验证所有依赖，无法并行。这会被利用构造拒绝服务攻击，使校验时间从 O(1) 退化为 O(n)。
2. **支持组队校验的并行任务分派**：禁止链式消费后，管理层可以将区块内所有交易的验证任务**独立地**分派给不同的校验员，校验员无需感知其他交易的验证结果。这是校验组高效协作的基础。
3. **简化实现**：状态转移逻辑无需在区块内维护临时 UTXO 集，直接查询已确认的状态存储即可。
4. **与 Evidcoin 交易费设计兼容**：Evidcoin 的交易费由输入输出金额差计算，禁止区块内消费确保了每笔交易的输入总是可以独立查询验证，不需要模拟前序交易的执行结果。

## Consequences（影响）

- 需在 `docs/proposal/08.UTXO-UTCO-State.md` 中明确添加此约束规则。
- `internal/utxo` 和 `internal/utco` 的状态转移函数中，查询函数仅访问已确认状态，不引用当前批次（区块）内的临时插入结果。
- 需在测试套件中添加反向测试：同区块内的链式消费尝试应被拒绝，并返回明确的错误码。
- 交易构建工具（如钱包实现）应在提示中说明此限制。
